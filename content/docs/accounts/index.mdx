title: 账号
description: 添加账号、查看状态、更换凭据、验证连通性与启用停用
---

一个账号由凭据与一组上游模型组成。同一供应商可配置多个账号，但一个请求只会发往其中一个，挑账号这一步称为选号。

选号先剔除三类账号：已停用的、处于冷却的、模型列表里没有这个模型的。剩下的按 `priority` 升序轮转。

冷却、失败转移与会话粘性的规则见[冷却与失败转移](/docs/accounts/failover)。每个子命令的完整参数表、输出列与 `--json` 字段见[账号命令](/docs/cli/account)。

## 添加账号

```bash
lax account add <名称> --provider deepseek --key sk-xxx
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--provider` | 必填，供应商名；地址与默认协议都从供应商行取 |
| `--key` | 凭据，三种给法见下文；不给时读环境变量 |
| `--models` | 手工声明该账号可用的模型，逗号分隔；同时写进模型目录并标为可用，留空则等 `model sync` |
| `--priority` | 选号顺序，数值小的优先，缺省 100 |

出站协议不在账号上：转发时按「该模型的探测结果 → 该模型声明的协议 → 供应商默认协议」推导（见[模型](/docs/models#查看探测结果)）。单价也不在账号上：模型单价属于「供应商 × 模型」，账号最多覆盖其中几项，见[模型单价](/docs/models#模型单价)。

会被拒绝的情况：

| 情况 | 结果 |
| --- | --- |
| 缺账号名或 `--provider` | 用法错误，打印用法行 |
| `--key`、标准输入、环境变量都取不到凭据 | 用法错误，提示三种给法 |
| 名称已存在 | 报错，提示换名称或先 `account rm` |
| `--price-in`、`--price-out`、`--price-cache-read`、`--price-cache-write` | 用法错误：单价属于模型，改用 `lax model price set`，套餐不同时加 `--account` 覆盖，见[模型单价](/docs/models#模型单价) |
| `--protocol` 或 `--base-url` | 用法错误：这两个参数已取消，地址与协议改用 `provider add` / `provider set` 声明 |
| 供应商不在供应商表里 | 报错，列出已知供应商；名称接近时给出最接近的一项，见[错误信息约定](/docs/cli#错误信息约定) |

凭据支持三种提供方式，明文不会进入日志与 `--json` 输出：

```bash
lax account add ds --provider deepseek --key sk-xxx       # 直接指定
lax account add ds --provider deepseek --key - < key.txt  # 从标准输入读取
LAX_KEY=sk-xxx lax account add ds --provider deepseek     # 读取环境变量
```

不给 `--key` 时依次读 `LAX_KEY` 与 `LAX_API_KEY`。`--key -` 需要管道或文件，直接在终端上跑会报错而不会挂在那里等输入。

## 查看账号列表

```bash
lax account ls
```

模型列有三种形态，含义不同：

| 形态 | 含义 |
| --- | --- |
| `12 可用 / 47 已登记` | 目录里登记了 47 个，其中 12 个可达性为可用，可承接请求 |
| `0 可用 / 47 已登记` | 已登记，但没有任何模型探测通过，当前无法承接请求 |
| `无模型（先 model sync）` | 尚无模型信息 |

「可用」只数可达性为 `allowed` 的行；「已登记」是同步、手填与探活留下的全部行。空列表不等同于支持全部模型：没有可用模型的账号不参与选号。

状态列显示 `正常`、`冷却至 15:04:05` 或 `停用`。

## 更换凭据

凭据失效或轮换时使用 `account set` 覆盖，不要删除账号后重建。这条命令只换凭据，单价不在它身上：改价用 [`model price set`](/docs/models#模型单价)。

删除会丢失三样东西：探测结果、每个模型上探测到的出站协议、请求记录的账号归属。

```bash
lax account set ds --key sk-yyy
```

旧凭据遗留的冷却与失败计数会在同一次写入中清零，账号重新启用。`update` 是 `set` 的同义词。

`account set` 的 `--json` 输出只有账号名、是否换了凭据、掩码后的新凭据，以及「冷却已清零、失败计数已清零、账号已启用」这三项，没有价格字段。

## 验证凭据

```bash
lax account test ds
```

`account test` 分两阶段，成败按第二阶段算：

| 阶段 | 发什么 | 能证明什么 |
| --- | --- | --- |
| 列表接口 | `GET` 模型列表地址，不消耗 token | 地址与连通性正常，并报出上游模型数 |
| 最小调用 | 一条 `max_tokens=1` 的真实请求，消耗少量 token | 凭据是否有效；这一步才是判成败的依据 |

列表接口 2xx 之后仍要走最小调用：公开的列表接口对任何 key 都回 200，光凭它判不出凭据好坏。列表接口返回 404、405、403，或者取不到列表地址、连不上时，也走最小调用。此时备注里会写清列表那一步为什么没成。列表接口自己返回 401、429、5xx 或其它 4xx 时，已经是结论，不再花一次调用。

最小调用用的模型名取账号模型列表的第一项。账号还没有模型时用 `default`，备注里会说明。`account test` 判定的是凭据与连通性，单个模型是否可用由 [`model probe`](/docs/models#探测可用性) 判定。

## 启用与停用

```bash
lax account disable ds   # 停用，不再参与选号
lax account enable ds    # 重新启用，同时清除冷却
lax account rm ds        # 删除账号及其模型行；请求记录保留
```

停用账号仍会出现在 `account ls` 里：列出它是为了区分账号故障与模型不存在。停用账号提供的模型不进入 `/v1/models` 清单，直接转发则返回 503。

手工启用意味着确认过凭据可用，因此同时清掉冷却与失败计数，不必等冷却到期。
