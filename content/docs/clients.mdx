要改的只有三处：base URL 指向本机网关，模型名取[探测通过](/docs/models#探测可用性)的可用值，凭据填入任意非空字符串。

lax 不改写任何客户端自身的配置文件，三项各自管什么如下：

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| base URL | 网关地址；anthropic 与 gemini 指向主机，两条 openai 协议要带上 `/v1` | 路径前缀多了或少了，请求落到未知路径，返回 404 |
| 模型名 | 探测通过的名称，按原文匹配，不做别名归一 | 填错返回 404，错误消息写明「没有账号提供模型 X」，排查见[客户端报「模型不存在」](/docs/faq#客户端报模型不存在) |
| 凭据 | 任意非空字符串 | 网关不校验，也不转发给上游；上游收到的始终是账号的凭据 |

先确认可用的模型名：

```bash
curl -s http://127.0.0.1:4567/v1/models
lax model ls
```

## Claude Code

使用 anthropic 协议，请求路径为 `POST /v1/messages`：

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:4567
export ANTHROPIC_AUTH_TOKEN=lax-local   # 本机不校验，任意非空值即可
export ANTHROPIC_MODEL=deepseek-v4-pro          # 必须是探测通过的模型名
```

## Codex

使用 openai-responses 协议，请求路径为 `POST /v1/responses`。在 `~/.codex/config.toml` 中将 provider 的 `base_url` 指向网关的 `/v1`：

```toml
[model_providers.lax]
name = "lax"
base_url = "http://127.0.0.1:4567/v1"
env_key = "LAX_KEY"

[profiles.local]
model_provider = "lax"
model = "gpt-5.1-codex"
```

```bash
export LAX_KEY=lax-local
```

## OpenAI SDK

使用 openai-chat 协议，base URL 同样指向 `/v1`：

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:4567/v1", api_key="lax-local")

resp = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "hi"}],
)
print(resp.choices[0].message.content)
```

流式与工具调用按 SDK 原有方式传参。网关按账号的出站协议决定原样直通还是按映射表转换，两条路径的差别见[直通与转换](/docs/gateway/conversion)。

## Anthropic SDK

使用 anthropic 协议，与 Claude Code 一样把 base URL 指向主机：

```python
from anthropic import Anthropic

client = Anthropic(base_url="http://127.0.0.1:4567", api_key="lax-local")

msg = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=256,
    messages=[{"role": "user", "content": "hi"}],
)
print(msg.content)
```

## Gemini SDK

使用 gemini 原生协议。base URL 只需指向主机，`/v1beta/models/…` 由 SDK 自行拼接：

```python
from google import genai

client = genai.Client(
    api_key="lax-local",
    http_options={"base_url": "http://127.0.0.1:4567"},
)

resp = client.models.generate_content(
    model="gemini-2.5-pro",
    contents="hi",
)
print(resp.text)
```

也可用 curl 直接调用原生路径：

```bash
curl -s http://127.0.0.1:4567/v1beta/models/deepseek-v4-pro:generateContent \
    -H 'Content-Type: application/json' \
    -d '{"contents":[{"role":"user","parts":[{"text":"用一句话介绍你自己"}]}]}'
```

流式调用只更换路径后缀，其余报文不变：

```bash
curl -s http://127.0.0.1:4567/v1beta/models/deepseek-v4-pro:generateContent \        # [!code --]
curl -s http://127.0.0.1:4567/v1beta/models/deepseek-v4-pro:streamGenerateContent \  # [!code ++]
    -H 'Content-Type: application/json' \
    -d '{"contents":[{"role":"user","parts":[{"text":"用一句话介绍你自己"}]}]}'
```

响应为 SSE（`data` 帧，末帧携带 `finishReason`）。

## 入站与出站协议不一致

客户端协议与出站协议不同时，转换由网关完成。systemone 不在转换范围内，它只与自己互通，见[与对话协议不互通](/docs/gateway/decision#与对话协议不互通)。

若客户端依赖仅原厂具备的能力，跨协议后该能力会丢失：

- 思考块签名；
- 服务端内置工具；
- 图片以外的多模态内容。

具体规则见[跨协议的能力差异](/docs/gateway/conversion#跨协议的能力差异)。

## 多客户端并用

[五条入站路径](/docs/gateway#五条入站路径)可同时启用。

同一账号被多种协议的客户端共用时，入站协议与出站协议一致的请求走直通，其余走转换。用量与冷却记录归属同一账号。

systemone 是例外：它只与自己的出站互通，不参与转换，因此对话客户端用不了决策模型，决策请求也发不到对话模型上（见[与对话协议不互通](/docs/gateway/decision#与对话协议不互通)）。决策请求由 TypeSafe SDK 或 `lax decide` 直发网关的 `/v1/systemone`。

冷却指账号连续失败后被暂时移出候选的一段时间，规则见[冷却与失败转移](/docs/accounts/failover#冷却与失败转移)。
