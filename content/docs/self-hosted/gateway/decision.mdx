---
title: 决策请求
description: systemone 协议的请求、响应、问题类型与互通边界
---

systemone 不是对话协议。它给一份材料与一组问题，返回每个问题的答案与概率，不产出文本。

## 请求

```bash
curl -s http://127.0.0.1:4567/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "typesafe/jev",
    "state": "付款失败三天，损失在扩大，请今天处理",
    "questions": {
      "urgent": {"type": "noul", "instructions": "是否要求今天处理"},
      "team": {
        "type": "choice",
        "instructions": "该交给哪个团队",
        "criteria": {"billing": "付款与扣款", "technical": "软件故障"}
      },
      "anger": {
        "type": "score",
        "instructions": "情绪强度",
        "criteria": ["平静", "不满", "愤怒"]
      }
    }
  }'
```

| 字段 | 说明 |
| --- | --- |
| `model` | 模型名，在请求体里 |
| `state` | 被判断的材料，纯文本或 JSON 都收 |
| `questions` | 问题对象，键是问题名 |

## 问题类型

| 类型 | 请求写法 | 答案字段 |
| --- | --- | --- |
| `noul` | `{"type":"noul","instructions":"…"}` | `noul`：回答“是”的概率 |
| `choice` | `{"type":"choice","instructions":"…","criteria":{"a":"说明","b":"说明"}}` | `choice`、`confidence`、`probabilities` |
| `score` | `{"type":"score","instructions":"…","criteria":["低","中","高"]}` | `score`、`confidence`、`legend`、`probabilities` |

`score` 的 `criteria` 按从低到高排列，至少两级。`choice` 的 `criteria` 是对象，键是选项名。

## 响应

```json
{
  "model": "jev-1.14.0",
  "answers": {
    "urgent": {"type": "noul", "noul": 0.98},
    "team": {"type": "choice", "choice": "billing", "confidence": 0.98},
    "anger": {"type": "score", "score": 1.08, "confidence": 0.86, "legend": {"1": "不满"}}
  },
  "usage": {"input_tokens": 386, "output_tokens": 61}
}
```

网关不改写响应；`model` 是上游返回的具体版本。

## 上限

| 项 | 上限 | 超过时 |
| --- | --- | --- |
| 一次请求的问题数 | 100 | 上游拒绝 |
| `state` 与全部问题合计 | 64K token | 上游拒绝 |
| `state` 与最长单个问题合计 | 32K token | 上游拒绝 |
| 请求体 | 8 MiB | 网关返回 413 |

请求带 `"stream": true` 时返回 400；这条协议没有 SSE。

## 接入一个决策模型

决策模型通常不在上游模型清单里，需要手写声明：

```bash
lax provider add typesafe --base-url https://api.typesafe.ai \
    --systemone /v1/systemone --default-protocol systemone
lax account add ts --provider typesafe --key sk-xxx
lax model add typesafe/jev --account ts --protocol systemone
lax model probe --account ts --model typesafe/jev --protocol systemone
```

只声明 systemone 路由时必须显式给 `--default-protocol systemone`。

## 不互通

| 请求 | 结果 |
| --- | --- |
| `/v1/systemone`，模型的有效出站协议是 systemone | 转发 |
| `/v1/systemone`，模型走其它协议 | 400，提示改用对话路径 |
| 对话路径，模型走 systemone | 400，提示改用 `/v1/systemone` |

一个模型只有一种有效出站协议。需要同时发对话与决策请求时，各用一个模型名。

## 命令行

```bash
lax model decide --model typesafe/jev --state "材料" \
    --noul "urgent=是否要求今天处理" \
    --choice "team=该交给哪个团队" --choice "team:billing=账单,technical=技术" \
    --score "anger=情绪强度" --score "anger:平静,不满,愤怒"
```

`--questions` 可以直接给整块 JSON，与逐条拼写互斥。输出表列出问题、类型、答案、概率与置信度；`--json` 原样输出上游的 `answers` 与 `usage`，另加 `model`、`account`、`latency_ms`。
