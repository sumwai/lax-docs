---
title: 协议转换
description: 直通、中间表示与跨协议时的字段取舍
---

入站与有效出站协议相同时，lax 走直通：请求体、响应体与流式帧原样转发。不同时，先解码成中间表示，再编码成目标协议。

## 直通

直通不代表完全无改动。网关仍会：

- 替换上游地址与路径；
- 移除或重写凭据头；
- 注入供应商声明的附加请求头；
- 记录请求、响应与用量。

请求体与响应体的字节不做重新编码。因此上游返回的独有字段在直通时能完整到达客户端。

## 中间表示

中间表示只保留各协议能对齐的字段：

| 类型 | 字段 |
| --- | --- |
| Request | `Model`、`System`、`Messages`、`Tools`、`ToolChoice`、`Thinking`、`ParallelToolCalls`、`MaxTokens`、`Temperature`、`TopP`、`Stop`、`Stream` |
| Message | 角色 + 内容块 |
| Block | `text`、`image`、`tool_use`、`tool_result`、`thinking` |
| Response | `ID`、`Model`、`Blocks`、`StopReason`、`Usage` |

## 同一概念落在哪里

| 概念 | anthropic | openai-chat | openai-responses |
| --- | --- | --- | --- |
| system | 顶层 `system` | 首条 `role=system` 消息 | 顶层 `instructions` |
| 对话中间的 system | 消息角色 `system` | 消息角色 `system` | 折进 `instructions`，位置丢失 |
| tool_use | assistant 消息里的 `tool_use` 块 | `tool_calls[]` | `function_call` item |
| tool_result | user 消息里的 `tool_result` 块 | 独立 `role=tool` 消息 | `function_call_output` item |
| 思考内容 | assistant 消息里的 `thinking` 块 | assistant 的 `reasoning_content` | output 里的 `reasoning` item |
| 结束原因 | `end_turn` / `max_tokens` / `tool_use` / `stop_sequence` | `stop` / `length` / `tool_calls` | `completed` / `incomplete` |
| 用量 | `input_tokens`、`output_tokens`、缓存读写 | `prompt_tokens`、`completion_tokens`、`cached_tokens` | `input_tokens`、`output_tokens`、`cached_tokens` |

## 会丢位置的字段

| 字段 | 结果 |
| --- | --- |
| 对话中间的 system 消息 | 转到 responses 或 gemini 时折进顶层 instructions，原位置丢失 |
| `developer` 角色 | 当作 system 处理，转到 responses 或 gemini 时折进 instructions |
| responses 的 `encrypted_content` | 不搬运；下游 responses 只写 `summary` |
| gemini 的内置工具 | 不搬运 |
| gemini 的思考内容 | 不搬运；请求侧的 `thinkingConfig` 仍会转换 |
| `tools[].strict` | 只在两条 openai 协议之间保留 |
| anthropic 的 `allowed_tools.mode=any` | 跨协议后退成 `auto` |

## 工具结果

anthropic 没有 `role=tool`。从 chat 或 responses 解出来的工具结果会折叠成一条 `role=user` 消息里的 `tool_result` 块；同一个 assistant 消息之后的多条结果按原顺序并进同一条 user 消息。

## 连续用户内容

工具结果之后紧跟的普通用户消息会并成同一条消息，避免某些上游把连续 user 消息判成非法。

## 思考配置

请求侧的思考配置在四种协议里名称不同：

| 目标 | 来源：预算 | 来源：档位 |
| --- | --- | --- |
| anthropic | `budget_tokens` 直传 | `minimal` 1024、`low` 2048、`medium` 4096、`high` 8192 |
| chat / responses | 预算 ≥ 8192 → `high`，≥ 2048 → `medium`，否则 `low` | `reasoning_effort` 直传 |
| gemini | `thinkingBudget` 直传 | 按 anthropic 的档位映射折成预算 |

客户端没给这类字段时，网关一个都不写。上游对不认识的参数会直接 400。

## 响应里的模型名

别名只影响请求方向。响应里的 `model` 字段保持上游返回的真名，不重写成客户端请求的别名。

## 截图式的字段对照

只搬运映射表里的字段。表外字段不会“尽量猜一个落点”：

```json
// [!code --]
{"model":"claude-sonnet","thinking":{"type":"enabled","budget_tokens":4096}}

// [!code ++]
{"model":"gpt-5.1","reasoning":{"effort":"medium"}}
```

这里 `budget_tokens` 4096 落在 `medium` 档；反向编回 anthropic 时只能得到 `budget_tokens: 4096`，无法恢复原始精度。

## 不支持转换的情况

| 情况 | 结果 |
| --- | --- |
| systemone 与对话协议互转 | 400 |
| 向量化与对话协议互转 | 400 |
| 语音与对话协议互转 | 400 |
| 流式但没有目标协议的流编码器 | 400，发送上游请求之前 |
