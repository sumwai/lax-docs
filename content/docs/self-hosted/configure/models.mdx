---
title: 模型管理
description: 从上游同步模型清单、探活可用性、手写模型声明与状态排障
---

`lax` 不预设固定模型列表，而是通过「同步目录 → 探活验证 → 进入选号」的流程动态维护可用模型。

对于没有列表接口的上游，也支持直接手写声明。

## 什么时候需要模型管理

- **新账号接入后**：拉取上游支持的模型名并验证哪些模型真正可调用。
- **上游发布新模型后**：增量同步新模型到本地目录，不影响已有账号配置。
- **上游无模型列表接口或需指定专用协议**：手工声明模型名与对应协议（如 `systemone`）。
- **客户端报模型不存在或调度异常**：查看模型在各账号上的可达性状态与冷却原因。

## 最短配置命令

```bash
# 1. 从上游拉取模型清单（不消耗 token）
lax model sync --account acct-a

# 2. 发送最小请求探活（可先用 --limit 5 小范围验证）
lax model probe --account acct-a --limit 5

# 3. 上游无列表接口时，手写声明模型
lax model add deepseek/deepseek-v4.1-flash --account acct-a

# 4. 查看模型列表与单个模型的详细状态
lax model ls --account acct-a
lax model show deepseek/deepseek-v4.1-flash --account acct-a
```

## 工作方式与进阶参数

### 1. 同步（`lax model sync`）

不加筛选参数时默认同步全部启用账号；也可以按供应商或账号范围同步：

```bash
lax model sync --provider deepseek
lax model sync --account acct-a --endpoint /v1/models
```

- `--endpoint` 仅在本次调用中临时覆盖模型列表路径，不会修改供应商配置。
- 同步支持四种清单格式：OpenAI 风格（`{"data":[...]}`）、通用风格（`{"models":[...]}`）、顶层数组（`[...]`）以及 Gemini（`{"models":[{"name":"models/..."}]}`，会自动去掉 `models/` 前缀并记录模型能力）。
- 只有 Gemini 清单支持自动分页（`pageSize=1000`，最多 10 页）；其他上游均按原样单次请求。

<Callout type="info">
`lax model sync` 只做增量补充：它不会删除已有模型，也不会把此前探活标记为 `forbidden` 或 `missing` 的模型恢复为可用。

只要任意账号同步失败，命令最终退出码为 `1`（不影响其他账号的同步结果）。
</Callout>

### 2. 探活（`lax model probe`）

探活会向每个模型发送一条真实最小请求（对话模型发 `max_tokens=1`，`systemone` 发最小决策请求），并将结果写入账号可达性：

```bash
lax model probe --account acct-a --model deepseek/deepseek-v4.1-flash
lax model probe --account acct-a --protocol anthropic --refresh
```

常用进阶参数：

- `--model <模型>` / `--protocol <协议>`：仅探测指定模型或协议。
- `--limit N` / `--concurrency N`：限制单账号本次探测数量或调整并发度。
- `--max-age <时长>` / `--refresh`：控制新鲜结果的复用窗口；`--refresh` 强制忽略缓存重新探测。

探活行为边界：

- 已经探测过且在新鲜窗口内的模型默认跳过；
- 探测过程中遇到 `401` 会立即停用该账号，并中止该账号后续模型的探测；
- 连接层失败先重试两次，仍失败时保留上一次的 `allowed` 状态；
- 收到 `403`、`404` 或明确提示模型不存在的 `400` 时，才会写入 `forbidden` 或 `missing`；
- 若全部账号都没有探出可用模型，退出码为 `1`。

### 3. 手写声明（`lax model add`）

当上游不提供列表接口，或需要为模型显式绑定专用协议时，使用手写声明：

```bash
lax model add typesafe/jev --account acct-c --protocol systemone
```

- `--account` 必填；`--provider` 可选（若传入则必须与账号所属供应商一致）。
- `--protocol` 可选；指定后写入该账号在该模型上的协议覆盖。
- 重复执行幂等：从 `forbidden`、`missing` 或 `error` 恢复为 `allowed` 时，会一并清除旧的 HTTP 错误状态与探测时间。

<Callout type="warn">
对于只声明了 `systemone` 等非对话路由的供应商，添加模型时需显式传入 `--protocol`（如 `--protocol systemone`），否则网关无法推导出有效出站协议。
</Callout>

### 4. 状态值与排障顺序

`lax model show` 只查询本地数据库，不发上游请求。

它返回的账号可达性状态含义如下：

| 可达性状态 | 含义 | 是否参与选号 |
| --- | --- | --- |
| `allowed` | 探活通过或手工声明可用（未探活的同步记录在 `ls` 中显示为「待探活」） | 是 |
| `forbidden` | 上游返回 `403`（权限或套餐限制） | 否 |
| `missing` | 上游返回不存在该模型 | 否 |
| `error` | 其他非 2xx 错误 | 否 |

此外，账号停用或模型处于冷却期时也不会参与选号（可通过 `lax model ls --json` 查看冷却截止时间）。

遇到模型不可用时，建议按以下顺序排查：

1. `lax model ls` 核对真实模型名或[别名](/self-hosted/concepts/how-it-works#模型名与别名)是否正确；
2. 若未登记，运行 `lax model sync` 或 `lax model add`；
3. 若显示「待探活」，运行 `lax model probe`；
4. 若状态为 `forbidden` / `missing` / `error`，运行 `lax model show <模型> --account <账号>` 查看 HTTP 状态码与错误信息；
5. 若状态正常但仍调度失败，运行 `lax route explain <模型>` 查看候选列表与冷却排除原因。
