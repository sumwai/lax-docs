供应商定义了「请求往哪里发」与「按什么协议格式发」。

## 什么时候需要配置供应商

网关初始化时已自带 9 个常见内置供应商（包括 `deepseek`、`anthropic`、`openai` 等）。

如果只使用内置供应商的官方地址，**无需新建供应商**，直接[添加账号](/self-hosted/configure/accounts)即可。

当需要以下操作时，使用 `lax provider`：

- 接入企业私有模型网关、本地部署推理服务或第三方中转（以下以自建供应商 `myco` 为例）；
- 覆盖内置供应商的 `Base URL` 或修改某条协议的路径；
- 自定义上游所需的鉴权请求头名称或格式。

### 内置供应商清单

| 供应商 | 默认 `Base URL` | 已声明路由 |
| --- | --- | --- |
| `anthropic` | `https://api.anthropic.com` | `anthropic` |
| `openai` | `https://api.openai.com` | `openai-chat`、`openai-responses`、`openai-embeddings`、`openai-speech`、`openai-transcriptions` |
| `deepseek` | `https://api.deepseek.com` | `openai-chat`、`anthropic` |
| `moonshot` | `https://api.moonshot.cn` | `openai-chat` |
| `kimi` | `https://api.moonshot.cn` | `openai-chat` |
| `openrouter` | `https://openrouter.ai/api` | `openai-chat` |
| `ollama` | `http://127.0.0.1:11434` | `openai-chat`、`openai-embeddings` |
| `commandcode` | `https://api.commandcode.ai/provider/v1` | `openai-chat`、`anthropic` |
| `google-gemini` | `https://generativelanguage.googleapis.com` | `gemini` |

## 最短配置命令

对于标准中转或自建网关，仅传 `--base-url` 即可自动补全 `openai-chat`、`openai-responses` 与 `anthropic` 三条核心对话路由：

```bash
lax provider add myco --base-url https://api.example.com
```

若需要显式指定或补充特定协议路径，可直接传入对应路由参数：

```bash
lax provider add myco --base-url https://api.example.com \
    --openai /v1/chat/completions \
    --anthropic /v1/messages
```

查看当前所有供应商（加 `--verbose` 可展开每条路由的完整地址与模型列表路径）：

```bash
lax provider ls
lax provider ls --verbose
```

输出中的「来源」列仅用于标识来源（内置、插件、自建），不限制后续修改，三类供应商均可执行 `set`、`unset` 与 `rm`。

## 工作方式与进阶参数

### 1. 八条协议路由与地址写法

新建供应商时，若仅传 `--base-url` 而不传任何路由参数，网关会自动生成三条核心对话路由（`/v1/chat/completions`、`/v1/responses`、`/v1/messages`；若 `Base URL` 已以 `/v1` 结尾，则自动去掉重复的 `/v1` 前缀）。

若显式声明路由，支持以下八个路由参数：

- 对话协议：`--openai`（`openai-chat`）、`--responses`（`openai-responses`）、`--anthropic`（`anthropic`）、`--gemini`（`gemini`）
- 专用协议：`--systemone`（`systemone`）、`--embeddings`（`openai-embeddings`）、`--speech`（`openai-speech`）、`--transcriptions`（`openai-transcriptions`）

每条路由既可以写**相对路径**（拼接在 `--base-url` 之后），也可以写**完整 URL**（忽略 `--base-url`，适合不同协议落在不同域名的场景），两者可以混用：

```bash
lax provider add myco \
    --anthropic https://open.bigmodel.cn/api/anthropic/v1/messages \
    --openai https://open.bigmodel.cn/api/coding/paas/v4/chat/completions \
    --responses https://open.bigmodel.cn/api/v1/responses \
    --models-path https://open.bigmodel.cn/api/coding/paas/v4/models
```

若声明 `gemini` 路由，由于模型名位于 URL 路径中，路由必须包含 `{model}` 占位符（替换时自动按 URL 路径段转义）：

```bash
lax provider add myco --base-url https://gemini.example.com \
    --gemini '/v1beta/models/{model}:generateContent'
```

<Callout type="warn">
只有当所有已声明路由与 `--models-path` 均使用完整 URL 时，才可省略 `--base-url`；只要存在任意一条相对路径，就必须提供 `--base-url`。

另外，路径中禁止出现 `..`，`{model}` 占位符仅允许用于 `gemini` 路由。
</Callout>

### 2. 默认协议推导

网关按以下固定顺序从供应商已声明的路由中自动推导默认协议：

1. `openai-chat`
2. `openai-responses`
3. `anthropic`

`gemini`、`systemone`、`embeddings`、`speech` 与 `transcriptions` 不会成为自动推导的默认对话协议；若某模型需要使用这些专用协议，请在模型维度显式绑定（如 `lax model add --protocol` 或 `lax model capability add`）。

### 3. 模型列表地址（`--models-path`）

执行 `lax model sync` 时，网关按以下优先级查找上游模型清单地址：

1. 供应商配置的 `--models-path`（支持相对路径或完整 URL）；
2. 该账号有效默认协议对应的模型列表路径；
3. 若路由为 `openai-chat`，自动推导 `/v1/models`。

如果上游没有提供模型列表接口，可在[模型管理](/self-hosted/configure/models)中用 `lax model add` 手写声明，或用 `lax model sync --endpoint` 临时指定路径。

### 4. 自定义凭据头

默认按出站协议自动生成鉴权头：`anthropic` 使用 `x-api-key: <key>`，`gemini` 使用 `x-goog-api-key: <key>`，其余协议使用 `Authorization: Bearer <key>`。

若上游要求非标准鉴权头，可通过 `--auth-header` 与 `--auth-scheme`（支持 `raw`、`bearer`、`bearer-semicolon`）覆盖：

```bash
lax provider set myco --auth-header X-Api-Key --auth-scheme raw
lax provider set myco --auth-header Authorization --auth-scheme bearer
```

声明自定义凭据头后，网关只发送指定的头，不再附加协议默认头。

如需附加其他固定请求头，见[网关请求头](/self-hosted/gateway)。

### 5. 修改、清除单项与删除

`lax provider set` 仅更新传入的参数，未传入的字段保持不变；清除单个字段使用 `lax provider unset`（幂等操作，字段不存在时不报错）：

```bash
lax provider set myco --responses /v1/responses
lax provider unset myco anthropic models-path
```

<Callout type="info">
`unset` 不允许把供应商删到一条路由都不剩；要彻底移除供应商请用 `lax provider rm myco`。

若该供应商下仍挂载着账号，默认拒绝删除，传入 `--force` 会删除供应商并自动停用关联账号（历史请求日志保留）。
</Callout>
