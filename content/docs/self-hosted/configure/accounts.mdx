账号代表一份挂载在指定供应商上的上游 `API Key`。

同一家供应商下可以添加多个账号（如 `acct-a`、`acct-b`），通过优先级与选号策略实现分流和容灾。

## 什么时候需要管理账号

- **首次接入或扩充账号池**：将新的上游 `API Key` 接入 `deepseek`、`myco` 等供应商。
- **凭据轮换或失效恢复**：上游 `API Key` 过期或触发 `401` 自动停用后，原位更换新密钥。
- **隔离排障或下线**：临时停用某个异常账号而不删除其历史用量与模型探测记录。

## 最短配置命令

```bash
# 添加账号（--priority 默认 100，数值越小越先尝试）
lax account add acct-a --provider deepseek --key sk-xxx
lax account add acct-b --provider deepseek --key sk-yyy --priority 200

# 查看账号列表与模型状态
lax account ls

# 更换 API Key（原地更新，保留探活结果与历史记录）
lax account set acct-a --key sk-new

# 测试账号连通性
lax account test acct-a

# 临时停用与重新启用
lax account disable acct-a
lax account enable acct-a

# 删除账号（无二次确认）
lax account rm acct-a
```

为避免明文 `API Key` 留在 shell 历史中，添加或更新时可从标准输入读取或使用环境变量 `LAX_KEY`：

```bash
lax account add acct-a --provider deepseek --key - < key.txt
LAX_KEY=sk-new lax account set acct-a
```

## 工作方式与进阶参数

### 1. 添加与查看

`lax account add` 的常用参数如下：

- `--provider`：所属供应商名称（必填）。
- `--key`：上游 `API Key`；写 `-` 从标准输入读取，省略时从 `LAX_KEY` 环境变量读取。
- `--priority`：同模型多账号下的优先级，默认 `100`，数值越小越优先。
- `--models`：逗号分隔的初始模型列表，直接写入模型目录并标为可用（不带上下文长度与价格元数据，常规场景建议改用 `lax model sync` 与 `probe`）。

`lax account ls` 输出中的「模型」列区分**可用**（探活通过或手工声明）与**已登记**（同步或历史留下的全部记录）。

<Callout type="info">
空的模型列表不代表「支持所有模型」。

没有任何可用模型的账号不会参与网关选号；添加账号后请继续执行[模型同步与探活](/self-hosted/configure/models)。
</Callout>

### 2. 原地更换 API Key（不要删号重建）

账号名是数据库中的主键，不支持直接改名。

删除账号会连带清理它的模型可达性、权重与选号统计（历史请求日志仍保留，账号列显示为 `-`）。

因此密钥过期或轮换时，务必使用 `lax account set`（别名 `update`）：网关会在同一事务内更新加密密钥、清除旧凭据留下的冷却与连续失败计数，并自动重新启用账号。

### 3. 两段式连通性测试（`lax account test`）

`lax account test <账号>` 用于验证账号凭据本身是否有效，分两段执行：

1. 先 `GET` 上游模型列表，验证地址与凭据头格式（不消耗 token）；
2. 若列表返回 2xx，再发送一条 `max_tokens=1` 的最小对话请求，验证凭据确实具备调用权限（部分上游的模型列表接口对任意密钥均返回 200）。

若上游列表接口不存在（404/405）、被拒绝（403）或连接失败，则直接跳过第一段进入第二段。

第二段默认取该账号列表中的第一个模型（列表为空时使用 `default`）。

<Callout type="info">
`lax account test` 只验证「凭据能不能调通」，不逐个验证模型权限。

某个具体模型能不能用，由 `lax model probe` 决定。
</Callout>

### 4. 自动停用与手动启停

- **401 自动停用**：真实转发过程中收到上游 `401` 时，网关自动停用该账号，避免失效凭据反复拖慢选号。更换有效密钥或执行 `lax account test` 成功、`lax account enable` 后可恢复。
- **403 不停用**：`403` 通常源于套餐权限或地区限制而非密钥失效，网关默认原样返回，不会停用账号。
- **`lax account disable / enable`**：手动停用后账号立即退出选号且不再出现在 `/v1/models` 中；重新启用时会清除该账号下所有模型的冷却状态。

### 5. `priority` 与权重、账号级覆盖的区别

- **`--priority`（账号属性）**：仅用于 `priority` 选号策略排序，数值越小越靠前。
- **权重（选号属性）**：仅用于 `weighted` 与 `softmax` 策略，通过 `lax route account set` 配置（详见[选号](/self-hosted/route)）。
- **账号级覆盖**：协议（`lax model add --protocol`）、单价（`lax model price set --account`）、额度监控设置（`lax quota set`）均支持按账号独立覆盖，详见[工作原理](/self-hosted/concepts/how-it-works#声明的能力与账号级覆盖)与[账号额度](/self-hosted/route/quota)。
