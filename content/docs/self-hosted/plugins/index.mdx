网关内置了常见供应商与报文协议。

遇到内置方言覆盖不了的特殊上游（例如私有语音接口、非标请求字段）时，可以通过插件描述供应商、模型目录与方言，不必修改网关源码或重新编译发布。

插件可以向网关提供：

- 一家或多家供应商及其路由、凭据头写法；
- 模型目录与模型别名；
- 方言（上游请求与响应的报文形状）及模型绑定。

## 两种运行时

| 运行时 | 信任级别 | 执行方式 | 适用范围 |
| --- | --- | --- | --- |
| `declarative` | `declarative` | 不执行代码，宿主按 `dialects.json` 求值 | 两条语音操作；对话、向量化与决策只能引用 `lax/` 宿主方言 |
| `moejs` | `sandboxed` | 每个 hook 在进程内 goja 沙箱执行 | 任意操作：可编排请求、解码响应与解码流 |

安装时 `--trust` 必须与 manifest 里的 `runtime` 一致；两种信任级别与沙箱限制详见[插件安全与运行时边界](/self-hosted/plugins/security#两种信任级别)。

## 插件包结构与安装流程

```text
插件包/
  lax.plugin.json    ID、版本、运行时、权限、供应商、路由、配置项
  dialects.json      声明式方言，或 hook 方言声明
  models.json        模型目录与操作绑定
  index.js           runtime=moejs 时的入口脚本
```

执行 `lax plugin install` 时，网关依次完成以下步骤：

1. 严格校验清单与引用关系，并确认信任级别。
2. 计算包哈希，拒绝重复版本与方言冲突。
3. 暂存到 `staging/` 后原子落盘到 `<数据目录>/plugins/installed/<插件 ID>/<版本>/`。
4. 逐家写入供应商与模型目录，并记录审计信息。

任意一步失败都会回滚包目录；已写入的供应商目录若需清理，可执行 `lax plugin rm` 或 `lax provider rm`。

## 安装插件

`lax plugin install` 支持四种来源：本地目录、完整 GitHub URL、GitHub 短形式和官方插件名。

```bash
# 本地目录（先用 --dry-run 预览写入内容）
lax plugin install ./my-plugin --dry-run
lax plugin install ./my-plugin
lax plugin install ./my-plugin --no-enable

# GitHub 来源
lax plugin install https://github.com/owner/repo/tree/main/plugins/my-plugin
lax plugin install github.com/owner/repo/plugins/my-plugin@v1.2.0

# 官方插件仓库（sumwai/lax-plugins）
lax plugin ls --available
lax plugin install doubao-seed-tts --trust sandboxed --yes
lax plugin install doubao-seed-tts@1.2.1 --trust sandboxed --yes
```

裸插件名的解析规则如下：

| 写法 | 解析来源 |
| --- | --- |
| `doubao-seed-tts` | 当前目录有同名目录时用本地目录；否则取官方仓库默认分支 |
| `doubao-seed-tts@1.2.1` | 官方仓库 tag `doubao-seed-tts-v1.2.1`（`@1.2.1` 与 `@v1.2.1` 等价） |
| `doubao-seed-tts@main` | 官方仓库的 `main` ref |
| `github.com/owner/repo/path@ref` | 指定 GitHub 仓库子目录 |
| `./local-dir` | 本地目录 |

省略 `--trust` 时按 manifest 的 `runtime` 自动推断；显式传入的 `--trust` 若与 `runtime` 不一致会报用法错误（退出码 `2`）。

从 GitHub 拉取归档时，解包会拒绝符号链接、特殊文件、重复条目、路径逃逸及超限归档，且每次只接受单个插件目录。

## 升级与回滚

已安装版本不可变，修改插件包内容必须升级 `version` 字段，同一版本不能覆盖。

安装第二个版本或升级时会切换活动版本指针，必须显式带 `--yes` 确认：

```bash
lax plugin update com.example.echo --source ./my-plugin-v2 --yes
lax plugin update com.example.echo --source doubao-seed-tts@1.2.1 --yes
lax plugin rollback com.example.echo --version 1.0.0
```

`update` 不带 `--yes` 时只打印将发生的变更，不带 `--trust` 则按新版本的 `runtime` 重新推断。

回滚前可用 `lax plugin ls` 或 `lax plugin show <id>` 查看本机已安装版本。

## 校验、日志、配置与热加载

```bash
lax plugin verify --all
lax plugin doctor com.example.echo
lax plugin logs com.example.echo --level warn --limit 100 --follow
lax plugin config get com.example.echo
lax plugin config set com.example.echo region cn
lax plugin config set com.example.echo token --stdin
lax plugin config unset com.example.echo region
lax plugin reload
```

| 命令 | 作用与说明 |
| --- | --- |
| `verify` | 静态校验包哈希、manifest 哈希、运行时与方言声明（不启动沙箱，未通过退出码 1） |
| `doctor` | 在静态校验基础上启动沙箱、试登记方言并检查导出钩子（未通过退出码 1） |
| `logs` | 查看插件运行日志，支持按级别过滤与 `--follow` 实时跟踪 |
| `config` | 读写 `options` 声明的非敏感配置项；敏感凭据不走配置项 |
| `reload` | 读取数据目录下的 `lax.pid` 并向 `serve` 发送 `SIGHUP`，重建并整表替换方言注册表 |

配置修改与插件启停对运行中网关的影响：

- `config set` 只落库，需执行 `lax plugin reload` 才被运行中的网关读取。
- `reload` 时在途请求继续使用换表前取到的方言跑完，重载失败只打日志不改当前注册表。
- 旧沙箱实例不会立即释放，反复 `reload` 会累积内存。

`config unset` 是幂等的：声明过但从未设置的键也以 `0` 退出，`--json` 返回 `"removed": false`，与真正删除时形状一致。

`logs --follow --json` 输出 NDJSON，每行一个完整对象，初始日志与后续新日志同形；没有新日志时不输出空 `[]`。

## 启停与卸载

```bash
lax plugin disable com.example.echo
lax plugin enable com.example.echo
lax plugin rm com.example.echo
lax plugin rm com.example.echo --purge
```

`disable` 后网关不再加载该插件的方言，运行中的网关需重启或 `reload` 才生效。

`rm` 会删除数据库记录与插件自带的供应商，并停用指向这些供应商的账号；默认保留包目录，加 `--purge` 一并删除。

重新安装后原有账号仍处于停用状态，需执行 `lax account enable` 恢复。
