---
title: 用量与花费
description: 按账号、模型或日期汇总 token、请求数与估算花费
---

每次上游尝试都会写一条请求记录，包括失败、换号前的尝试与探活。`usage` 从这些记录汇总用量与花费。

## 基本用法

```bash
lax usage
lax usage --since 24h
lax usage --since 7d --by model
lax usage --by day --from '-7d 00:00'
lax usage --account ds
lax usage --provider deepseek
lax usage --model deepseek-v4-pro
```

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--by` | 分组维度：`account`、`model`、`day` | `account` |
| `--since` | 相对时间：`30s`、`15m`、`24h`、`7d`、`3w` | `7d` |
| `--from` / `--to` | 绝对或相对时间范围；与 `--since` 互斥 | — |
| `--account` | 只统计这个账号 | — |
| `--model` | 只统计这个真实模型；别名会先解析 | — |
| `--provider` | 只统计这家供应商的账号 | — |

`--since`、`--from`、`--to` 支持带空格的写法，例如 `--from '-1d 11:00'`。含空格时要加引号。

## 时间范围写法

| 写法 | 含义 |
| --- | --- |
| `30s`、`15m`、`24h`、`7d`、`3w` | 相对当前时间向前 |
| `11:00` | 今天 11:00 |
| `-1d 11:00` | 昨天 11:00 |
| `2026-10-01` | 本地时区的当天 00:00 |
| `2026-10-01 11:30` | 本地时区的具体时间 |
| RFC3339 | 带时区的绝对时间 |

`--to` 是开区间，只写日期或 `-1d` 时包含当天结束。

## 人读输出

| 列 | 内容 |
| --- | --- |
| 账号 / 模型 / 日期 | 分组键，随 `--by` 变化 |
| 请求 | 请求数，包含失败尝试 |
| 输入 token | 上游原值 |
| 输出 token | 上游原值 |
| 思考 token | 上游单独上报的思考数 |
| 缓存读 token | 命中缓存的输入 |
| 缓存写 token | 写入缓存的部分 |
| 合成字符 | 语音合成的字符数 |
| 音频秒 | 转写或合成的音频时长 |
| 估算花费 | 按账号与模型现算；缺价写“未定价” |

最后一行是合计。未定价的行不按 0 累加，输出会说明有几行没有计入合计。

## JSON 输出

```bash
lax usage --json
lax usage --by day --json
```

每项字段：

| 字段 | 内容 |
| --- | --- |
| `key` | 分组键 |
| `requests` | 请求数 |
| `in_tokens` | 输入 token |
| `out_tokens` | 输出 token |
| `reasoning_tokens` | 思考 token |
| `cache_read` | 缓存读 token |
| `cache_write` | 缓存写 token |
| `tts_chars` | 合成字符 |
| `audio_seconds` | 音频秒 |
| `cost` | 估算花费；整组未定价时为 `null` |

## 花费口径

花费 = 各用量 × 对应单价之和。价格取值顺序与单位见[模型定价](/docs/self-hosted/configure/pricing)。

几个容易混淆的点：

- 思考 token 不单独计价。上游把它排在输出之外时，输出单价已覆盖；anthropic 报在输出里时也不重复算。
- 缓存读与缓存写有独立单价；没填时回退到输入价。
- 请求记录保存的是上游原值；估算花费在读取时现算，不落库。
- 探活请求同样计入用量。

## 排除探活费用？

目前不能从 `usage` 里单独排除探活。探活的记录与转发记录在同一张表里。需要区分时用 `lax log tail` 看单条记录，或按时间窗口单独统计一次探活前后的差值。

## 没有记录时

输出 `最近 7d 没有请求记录`，退出码 0。这不表示上游不可用；先确认 `serve` 是否在运行，以及请求是否真的进入网关。
