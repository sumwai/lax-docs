---
title: 健康检查与诊断
description: 使用 lax doctor 检查配置、数据目录、加密密钥、端口与数据库连通性
---

首次启动前、修改配置后，或 `lax serve` 启动失败时，先运行 `lax doctor` 对运行环境做一次全面体检：

```bash
lax doctor
lax doctor --json
```

`lax doctor` 只检查现状，不会修改账号、模型、策略与请求记录。

执行过程中会确保数据目录存在，通过写入并立即删除临时文件测试目录可写性，随后尝试连接数据库（若 SQLite 数据库文件不存在，会自动创建空库与表结构）。

即使某一项检查失败，其余检查仍会继续执行，命令最终以退出码 `1` 结束。

## 检查项一览

| 检查项 | 检查内容 | 失败时处理建议 |
| --- | --- | --- |
| 配置文件 | 文件是否存在、可读且 JSON 可解析 | 运行 `lax init`，或核对 `--config` 路径 |
| 数据目录可写 | 数据库所在目录能否写入文件 | 检查目录权限与磁盘剩余空间 |
| 加密密钥 | `secret.key` 是否存在且可读 | 恢复备份的密钥；重新生成会导致旧凭据无法解密 |
| 配置解析 | 监听地址、驱动类型与 DSN 能否解析 | 修正 `config.json` 中的对应字段 |
| 端口 | 尝试监听配置中的绑定地址 | 更换空闲端口或停止占用该端口的进程 |
| 数据库 | 能否建立连接且账号数据可读 | 检查文件路径、驱动类型与 DSN 权限 |
| 旧数据搬迁 | 新库为空且旧路径仍有数据时发出提示 | 按提示将旧库与密钥移至新数据目录 |

## 脱敏输出示例

默认终端输出示例：

```text
✓ 配置文件      /path/to/.config/lax/config.json
✓ 数据目录可写  /path/to/.local/share/lax
✓ 加密密钥      /path/to/.local/share/lax/secret.key
✓ 配置解析      127.0.0.1:4567 (sqlite)
✗ 端口          listen tcp 127.0.0.1:4567: bind: address already in use
✓ 数据库        /path/to/.local/share/lax/lax.db (3 个账号)
```

`lax serve` 正在运行时，端口检查项会报告地址已被占用，属于预期结果而非故障。

传入 `--json` 时返回检查项数组，顶层不包含汇总字段，只要任意一项 `ok` 为 `false` 即返回退出码 `1`：

```json
[
  {"name": "配置文件", "ok": true, "note": "/path/to/.config/lax/config.json"},
  {"name": "端口", "ok": false, "note": "listen tcp 127.0.0.1:4567: bind: address already in use"}
]
```

## 常见失败与排障建议

### 尚未初始化

输出 `尚未初始化，先运行 lax init` 说明缺少配置文件，或 `--config` 指向了错误路径。

核对 `$XDG_CONFIG_HOME/lax/config.json` 是否存在，或执行 `lax init` 初始化。

### 数据库被删或路径指错

<Callout type="warn" title="注意区分空库与数据丢失">
`lax doctor` 打开不存在的 SQLite 路径时会自动建出空库与表结构，因此该项通常不会直接报错，而是显示账号数为 `0`。

若发现账号与用量记录消失，先核对 `--db` 参数与 `config.json` 中的 `db` 路径是否仍指向原数据库；`lax init` 只会重建空库，不会恢复原有账号与密钥。
</Callout>

若旧路径下仍有数据，「旧数据搬迁」检查项会失败并输出搬迁指引。

按提示将旧库与 `secret.key` 移至新数据目录即可，切勿在已有账号数据时覆盖或重新生成 `secret.key`。

### 端口占用

两个 `lax serve` 实例不能监听同一个地址。

排查时可停止旧进程，或在启动时通过 `--addr` 临时指定空闲端口，也可以直接修改 `config.json` 中的监听地址：

```bash
lax serve --addr 127.0.0.1:4568
```

### 数据库打不开

先确认 `config.json` 中的 `driver` 与 `dsn` 是否匹配。

使用 SQLite 时检查数据库文件与父目录权限；使用 PostgreSQL 或 MySQL 时确认数据库服务处于运行状态，且连接账号拥有建表权限。
