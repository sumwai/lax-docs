description: doctor 检查什么、失败时怎么处理
---

```bash
lax doctor
lax doctor --json
```

`doctor` 逐项检查运行所需的环境。任一项失败时命令以退出码 1 结束，但其余检查仍会继续。

## 检查项

| 项 | 检查 | 失败时 |
| --- | --- | --- |
| 配置文件 | 文件存在、可读、JSON 可解析 | 运行 `lax init`，或检查 `--config` 路径 |
| 数据目录可写 | 数据库所在目录能否写入 | 检查目录权限与磁盘空间 |
| 加密密钥 | `secret.key` 是否存在 | 恢复备份的密钥；重新生成会让旧凭据无法解密 |
| 配置解析 | 监听地址、后端与 DSN 能否解析 | 修正 `config.json` |
| 端口 | 尝试监听配置里的地址 | 换端口或停掉占用的进程 |
| 数据库 | 能否打开、账号表是否可读 | 检查路径、后端与 DSN |
| 旧数据搬迁 | 新库为空且旧路径还有数据时提示 | 按提示把旧库与密钥移到新数据目录 |

`serve` 正在运行时，端口项通常显示占用，这是预期结果，不是故障。

## JSON 输出

```json
[
  {"name": "配置文件", "ok": true, "note": "/home/someone/.config/lax/config.json"},
  {"name": "端口", "ok": false, "note": "listen tcp 127.0.0.1:4567: bind: address already in use"}
]
```

顶层是检查项数组，没有单独的整体结论字段。任一项 `ok` 为 `false` 时，命令以退出码 1 结束。

## 常见失败

### 尚未初始化

```text
尚未初始化，先运行 lax init
```

没有配置文件，或 `--config` 指错了位置。

### 数据库不存在

```text
数据库不存在，先运行 lax init
```

数据库文件被删掉或 `--db` 指错。`init` 会重建空库，但不会恢复账号与密钥。

### 端口占用

```bash
lax serve --addr 127.0.0.1:4568
```

或修改 `config.json` 的 `addr`。两个 `serve` 不能监听同一个地址。

### 数据库打不开

先确认 `driver` 与 `dsn` 是否匹配。SQLite 检查文件权限与父目录；PostgreSQL/MySQL 检查服务是否在运行、账号是否有建表权限。
