## 启动与部署

### 网关无法启动

先运行自检定位问题：

```bash
lax doctor
```

- **端口已被占用**：使用 `lax serve --addr 127.0.0.1:4568` 更换端口，或排查原有进程。
- **提示「尚未初始化」**：先运行 `lax init`。
- **提示「数据库不存在」**：核对 `--db` 参数或 `config.json` 中的路径。

### 能直接暴露到公网吗

不要直接把默认监听端口映射到公网。`lax serve` 本身不校验入站凭据，默认仅监听 `127.0.0.1:4567`（见[命令行参考](/self-hosted/cli#serve)）。

对外提供服务前，必须在前方挂载反向代理，启用 TLS、入站认证与访问来源限制。

### 支持 Windows 吗

官方预编译发布包不覆盖 Windows（见[安装](/self-hosted/install)），因为 `lax serve` 与 `lax plugin reload` 依赖 Unix 信号。

在 Windows 上只能自行从源码编译，且信号相关功能不可用。

### 迁移主机怎么搬

必须将配置文件、`lax.db`、`secret.key` 与 `plugins/` 目录一并迁移（详见[数据与升级](/self-hosted/operate/data-upgrade)）。

如果只迁移数据库而遗漏 `secret.key`，已入库的上游 `API Key` 将无法解密。

## 模型与账号

### 客户端报模型不存在

按以下顺序逐项核对：

1. 运行 `lax model ls` 确认模型名拼写是否与目录一致；
2. 若客户端传入的是别名，运行 `lax model alias ls` 确认别名映射是否有效；
3. 确认提供该模型的账号处于启用状态，且该模型已完成探活或手工声明（状态需为 `allowed`，见[模型管理](/self-hosted/configure/models)）。

`lax model sync` 只负责拉取模型清单，不代表模型已验证可用。

### 两个账号为什么请求只走一个

默认选号策略为 `priority`，始终优先尝试 `priority` 数值最小的账号。

若希望按轮询或权重分摊流量，需通过 `lax route set` 切换为 `rotate` 或 `weighted`，并检查会话粘性（`--sticky`）是否将同一会话固定到了首个账号（详见[选号](/self-hosted/route)）。

### 插件安装后不生效

1. 运行 `lax plugin ls` 确认插件状态与启用情况；
2. 运行 `lax plugin doctor` 检查插件包与沙箱环境；
3. 对运行中的网关执行 `lax plugin reload`，或重启 `lax serve`；
4. 若此前曾删除插件导致关联账号被停用，需手动执行 `lax account enable <账号>` 恢复。

## 错误与冷却

### 请求持续失败并进入冷却

```bash
lax log tail -n 20
lax route explain <模型>
```

冷却按「账号 + 模型」维度隔离记录，单个模型触发限流不会影响同一账号下的其他模型。

各类错误的默认冷却时长与上限见[失败如何分类](/self-hosted/concepts/request-lifecycle#失败如何分类)。当所有候选账号均处于冷却期时，网关返回 `503`。

### 上游返回 401

网关收到上游 `401` 后会自动停用该账号。

无需删除重建，直接原地更换有效密钥即可清除冷却与失败计数并恢复启用：

```bash
lax account set <账号> --key <新 API Key>
```

### 上游返回 403

`403` 通常源于套餐权限、模型未开通或地区限制，而非 `API Key` 失效。

网关默认将其原样返回给客户端，不停用账号、不计入冷却也不换号。如需自定义 `403` 的处置动作，可在[失败处理](/self-hosted/route/failure)中配置规则覆盖。

### 为什么 400 不换号

`400` 通常意味着请求本身存在问题（模型名错误、参数非法或协议不兼容）。

更换其他账号重发同一条错误请求大概率仍会失败，因此网关默认直接返回错误。

### 流式请求中断后为什么不重试

一旦网关已向客户端写出流式响应字节，便无法撤回已输出的内容。

若中途换号重试，会将两段不同的响应拼接在一起，因此只记录失败而不换号。

## 额度与用量

### 用量里为什么有 0 花费或未定价

在 `lax usage` 中，「免费（`0.00`）」与「未定价」含义不同：

- 显示 `0.00`（`--json` 中 `cost` 为 `0`）：模型单价明确配置为 `0`。
- 显示「未定价」（`--json` 中 `cost` 为 `null`）：该模型或账号尚未配置单价，不计入总花费。

### 探活费用能排除吗

目前不支持按请求类型单独排除。

`lax model probe` 发出的最小验证请求同样会写入请求日志并计入用量汇总。

### 刷新额度会停用账号或计入用量吗

不会。`lax quota refresh` 只更新账号的只读额度快照，不修改账号启用状态，也不写入请求日志（详见[账号额度](/self-hosted/route/quota)）。

整次刷新失败且包含 `401`/`403` 时，仅将快照状态标记为「凭据被拒」；只有真实转发请求收到 `401` 才会停用账号。

### 设置了额度过滤为什么账号仍被选中

`--quota-min-usd` 仅排除「折合余额已知且低于阈值」的账号；从未刷新、汇率未知或余额未知的账号会被保留（详见[账号额度](/self-hosted/route/quota)）。

请先运行 `lax quota refresh <账号>` 并通过 `lax quota show <账号>` 确认余额已成功折算。

### 为什么余额或剩余比例显示为 `-`

常见原因是尚未刷新快照，或者上游返回的币种不是 `USD` 且未设置 `--fx-rate` 汇率。

此外，DeepSeek 上游仅返回余额而不提供总额上限，因此其剩余比例始终显示为 `-`。

### 额度监控支持哪些供应商与场景

目前额度监控仅支持 `CommandCode` 与 `DeepSeek`，其他供应商会显示「不支持」并在刷新时自动跳过。

`lax quota` 属于管理员侧的只读上游余额监控，不提供多租户配额分配或扣减功能。
