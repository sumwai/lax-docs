## 网关起不来

先看端口是否被占用：

```bash
lax doctor
```

端口项失败时，换一个地址：

```bash
lax serve --addr 127.0.0.1:4568
```

如果提示“尚未初始化”，运行 `lax init`。如果提示“数据库不存在”，检查 `--db` 或配置里的路径。

## 客户端报模型不存在

1. 用 `lax model ls` 确认模型名；
2. 确认提供它的账号已启用；
3. 确认模型在某个账号上探活通过；
4. 如果客户端写的是别名，用 `lax model alias ls` 看是否能解析。

同步只把名字写进模型目录，不判定可用性；判断依据见[状态值](/docs/self-hosted/configure/models#状态值)。

## 请求持续失败并进入冷却

```bash
lax log tail -n 20
lax route explain <模型>
```

冷却按账号 + 模型记录。429、5xx 与连接层失败各自的起算时长与上限见[失败如何分类](/docs/self-hosted/concepts/request-lifecycle#失败如何分类)。

如果所有候选都在冷却，网关返回 503。等冷却结束，或调整候选账号。

## 上游 401

账号会被停用。换 key：

```bash
lax account set <账号> --key <新 key>
```

换 key 会清掉冷却、失败次数并重新启用账号，不需要删除重建。

## 上游 403

403 通常是套餐、模型权限或区域限制，不是凭据失效；默认原样返回，不停用、不冷却、不换号。规则可以改写这一行为，见[失败处理](/docs/self-hosted/route/failure#匹配顺序)。先确认这个账号是否真的有这个模型的权限。

## 同一个账号的其它模型也被限流了吗

不会。冷却按账号 + 模型隔离。一个模型 429 不影响同账号的其它模型。

## 为什么有两个账号，请求只走一个

默认策略是 `priority`，按账号的 `priority` 升序先试第一个。要平均分摊，改用 `rotate` 或 `weighted`；要看会话粘性是否把请求固定到同一个账号。

## 为什么 400 不换号

400 通常是请求本身有问题：模型名错、参数不合法、协议不相通。换账号重发同一条错误请求只会重复失败，因此直接返回。

## 流式请求中断后为什么不重试

已经向客户端写出字节后，无法撤回半截响应。重试会把两段响应拼在一起，因此记录失败但不换号。

## 用量里为什么有 0 花费

两种可能：价格确实填了 0，或这一组请求未定价。未定价显示“未定价”，`--json` 里 `cost` 为 `null`；免费显示 `0.00`。

## 探活费用能排除吗

目前不能按请求类型单独排除。探活请求也写请求记录并进入用量汇总。

## 刷新额度会停用账号或计入用量吗

不会。额度刷新只写额度快照，不改账号状态，也不写请求记录；完整说明见[手动刷新](/docs/self-hosted/route/quota#手动刷新)。

整次刷新失败且其中出现 401 或 403 时，只把状态记为「凭据被拒」。只有真实转发请求收到 401 才会停用账号。

## 为什么设置了额度过滤，账号仍会被选中

`--quota-min-usd` 只排除折合余额已知且低于阈值的账号；从未刷新、汇率未知或余额未知的账号一律保留，原因见[参与选号](/docs/self-hosted/route/quota#参与选号)。

先运行 `lax quota refresh <账号>`，再用 `lax quota show <账号>` 确认余额与折合 USD 是否已知。

## 为什么余额或剩余比例显示 `-`

常见原因是还没有快照，或币种不是 USD 且没有设置 `--fx-rate`。DeepSeek 只报余额，没有总额，所以剩余比例始终是 `-`。

没有汇率时原币种余额照存，但折合 USD 与剩余比例未知；这类账号也不会被 `--quota-min-usd` 排除。

## 额度监控支持哪些供应商

目前只支持 CommandCode 与 DeepSeek。其它供应商显示「不支持」，`quota refresh` 会跳过，不算失败。

`quota set --source` 可以强制指定来源；`off` 关闭监控，旧快照不再参与选号。

## 账号额度和多租户配额有什么区别

账号额度是管理员侧针对上游账号的只读监控，用来查看余额与到期时间，可选参与选号，不做分配、扣减或计费。

多租户配额是按最终用户分配与扣减的额度。lax 不提供多租户与配额分配。详见[账号额度](/docs/self-hosted/route/quota)。

## 能放到公网吗

自部署时，网关本身不校验入站凭据，默认只监听回环地址，默认值见[命令行参考](/docs/self-hosted/cli#serve)。对外提供服务前必须加认证与 TLS，并限制访问来源；不要把默认监听地址直接映射到公网。`https://larkax.com` 已在入口加了 Bearer API Key 鉴权与 TLS。

## Windows 支持吗

发布包不覆盖 Windows，原因与可用范围见[安装](/docs/self-hosted/install#两种安装方式)。在 Windows 上只能自行构建，并预期部分功能不可用。

## 插件装完不生效

1. `lax plugin ls` 看状态；
2. `lax plugin doctor` 看包与沙箱；
3. 正在运行的网关执行 `lax plugin reload`，或重启 `serve`；
4. 检查账号是否被插件删除时的停用状态影响，需要 `account enable`。

## 换机器怎么搬

配置、数据库、`secret.key` 与 `plugins/` 一起搬。只搬数据库会导致旧凭据无法解密，插件包也会缺失。
