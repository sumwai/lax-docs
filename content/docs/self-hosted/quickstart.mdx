---
title: 首次配置
description: 5 分钟内完成账号接入、模型同步与第一条网关请求
---

本页假设已完成[安装](/self-hosted/install)与 `lax init`。

以下步骤以内置供应商 `deepseek`、账号名 `acct-a` 与模型 `deepseek/deepseek-v4.1-flash` 为例，全程在同一台主机上跑通。

## 1. 添加上游账号

```bash
lax account add acct-a --provider deepseek --key sk-xxx
```

`acct-a` 是自取的账号名，`deepseek` 是网关内置的供应商名。

若不想把 `API Key` 留在 shell 历史中，可改用标准输入或环境变量 `LAX_KEY`（详见[账号](/self-hosted/configure/accounts)）。

## 2. 同步并探测模型

从上游拉取模型清单并写入本地目录：

```bash
lax model sync --account acct-a
```

`sync` 只拉取模型名，不验证账号权限。

接着运行探活，只有探测通过的模型才会进入选号池（可用 `--limit 3` 先小范围验证）：

```bash
lax model probe --account acct-a
```

查看当前账号下已就绪的模型：

```bash
lax model ls --account acct-a
```

详见[模型管理](/self-hosted/configure/models)。

## 3. 启动网关

```bash
lax serve
```

网关默认监听 `127.0.0.1:4567`，在前台持续运行（按 `Ctrl-C` 退出）。

如需修改监听地址，可临时传入 `--addr 127.0.0.1:4568` 或在 `config.json` 中配置（详见[网关](/self-hosted/gateway)）。

<Callout type="warn">
`lax serve` 默认仅监听本机回环地址且不校验入站凭据。

对外提供服务前，必须在前方挂载反向代理、TLS 与访问控制。
</Callout>

## 4. 发送第一条请求

另开一个终端，直接向默认地址 `127.0.0.1:4567` 发送 OpenAI 兼容格式请求：

```bash
curl -s http://127.0.0.1:4567/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "deepseek/deepseek-v4.1-flash",
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'
```

预期返回标准 OpenAI 对话响应 JSON（字段已做精简示意）：

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "model": "deepseek/deepseek-v4.1-flash",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! I am ready to help you."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 14,
    "completion_tokens": 9,
    "total_tokens": 23
  }
}
```

也可以不经过 HTTP 客户端，直接用 CLI 发起一次快速验证：

```bash
lax model call "用一句话介绍自己" --model deepseek/deepseek-v4.1-flash --debug
```

## 5. 查看请求记录与用量

```bash
lax log tail
lax usage
```

`lax log tail` 输出每次转发尝试的协议、命中账号、HTTP 状态、token 数与耗时。

`lax usage` 按账号、模型或日期汇总用量与估算花费（详见[用量与日志](/self-hosted/operate/logs-usage)）。
