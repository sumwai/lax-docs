---
title: 预演选号
description: 不发请求查看候选顺序、排除原因与 softmax 概率
---

`route explain` 用当前策略、权重与统计预演一次选号。它只读数据库，不发上游请求，不写请求记录，也不改冷却。

## 基本用法

```bash
lax route explain glm-4.6
lax route explain glm-4.6 --session demo --seed 42
lax route explain glm-4.6 --json
```

| 参数 | 作用 |
| --- | --- |
| `<模型>` | 必填；可以是别名，输出里写解析后的真实模型 |
| `--session` | 模拟一个会话键，观察粘性效果 |
| `--seed` | softmax 的随机种子；相同数据与种子结果一致 |

## 人读输出

```text
模型 model-a：weighted / 会话 prefer / 来源 模型
顺序  账号    权重  样本  成功率  平均延迟  得分   概率
1     acct-a  3     0     50%     -         0.700  -
2     acct-b  1     0     50%     -         0.300  -
最终顺序：acct-a → acct-b
```

| 列 | 含义 |
| --- | --- |
| 顺序 | 本次排出的尝试顺序 |
| 账号 | 账号名 |
| 权重 | 这个模型上的有效权重 |
| 样本 | 统计窗口内的账号相关请求数 |
| 成功率 | 平滑后的成功率 |
| 平均延迟 | 成功请求的平均耗时；没有样本时显示 `-` |
| 得分 | 综合评分 |
| 概率 | softmax 抽中的概率；非 softmax 策略显示 `-` |

被排除的账号会单独列一行：

```text
排除：acct-c（正在冷却）；acct-d（没有声明这个模型）
```

## 用预演排障

| 现象 | 预演里看什么 |
| --- | --- |
| 请求总是走同一个账号 | `policy.sticky` 是否为 `prefer` 或 `strict` |
| 期望的账号没被选中 | `excluded` 里是否有它，以及原因 |
| 成功率策略没有效果 | `attempts` 是否达到 `min_samples`；样本不足时成功率都在 0.5 附近 |
| softmax 看起来随机 | 固定 `--seed` 复现；看 `temperature` 与 `explore` |
| 权重没有生效 | `policy.strategy` 是否为 `weighted` 或 `softmax`；候选的 `weight` 是否正确 |

## 预演与真实请求的差异

- 预演使用调用时刻的数据库快照；真实请求到达时会重新读取。
- 预演不消耗上游额度，也不产生新样本；真实请求的结果会改变下一次的成功率与延迟。
- 预演不执行上游请求，因此不会发现上游刚刚返回 429 或 5xx。
