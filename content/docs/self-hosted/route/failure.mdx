description: 请求失败后如何自动冷却与切号，以及如何用 lax route explain 排查选号结果
---

请求发往上游失败时，网关会按状态码或自定义规则决定重试、冷却、停用还是切到下一个候选账号。

遇到「为什么选了 A 账号没选 B 账号」或「某个账号怎么没进候选」时，再用 `lax route explain` 现场预演即可定位原因。

## 请求失败后怎么处理

没有配置自定义规则时，网关默认只看响应状态码：

| 上游返回 | 默认处理 |
| --- | --- |
| `401` | 永久停用账号，直接返回客户端（判定规则见[启用与停用](/self-hosted/configure/accounts#启用与停用)） |
| `403` 与普通 `400` | 原样返回客户端，不重试、不冷却、不停用，也不计入选号统计 |
| `429`、`408`、`5xx` 与连接层失败 | 冷却该「账号 + 模型」一段时间，然后换下一个候选账号继续尝试 |

仅靠状态码有一个盲区：很多上游在余额不足、套餐到期时返回 `400`，默认处理会把它当成客户端写错了请求，既不冷却也不换号，同一会话还会继续粘在这个不可用账号上。

通过 `lax route policy` 可以把失败处理改为按条件与动作匹配，规则存在数据库里，改完立即生效，不需要重启。

## 自定义失败处理规则

一条规则由**条件**和**动作**组成：条件之间是「并且」，同一条件内的多个值是「或者」。

### 条件

| 条件 | 写法 | 说明 |
| --- | --- | --- |
| 账号 | `--account <账号>` | 只匹配指定账号 |
| 供应商 | `--provider <供应商>` | 只匹配指定供应商 |
| 模型 | `--model <模型>` | 只匹配指定模型，支持别名 |
| 状态码 | `--status 400,429,5xx` | `400`–`599` 的具体码，或 `4xx`、`5xx`；可逗号分隔或重复写 |
| 错误文本 | `--error-contains "insufficient credits"` | 大小写不敏感的子串；可重复写，任意一条命中即可 |
| 错误正则 | `--error-regex "<正则>"` | Go 正则表达式，最长 512 字符 |
| 全部错误 | `--all-errors` | 在其余条件范围内匹配任何状态与错误文本 |

错误文本取网关已经脱敏并截断到 300 字符之后的内容。

未写 `--status`、`--error-contains`、`--error-regex` 的规则必须显式带 `--all-errors`（且不能与这三项同用），防止漏写条件后把正常 `400` 误判为账号故障。

### 动作

| 动作 | 写法 | 说明 |
| --- | --- | --- |
| 重试 | `--retry N` | 同一账号同一模型再试 `N` 次（1–10），总调用 `N+1` 次 |
| 重试间隔 | `--retry-base 时长` | 第一次等待时长，默认 `500ms`，范围 `100ms`–`10s` |
| 冷却 | `--cooldown 时长` | 冷却 1 秒到 30 天（30 天写成 `720h`）；带 `--model` 只冷却账号-模型，不带则冷却整个账号 |
| 停用 | `--disable` | 永久停用整个账号，需手工 `lax account enable` 恢复 |
| 换号 | `--next_route` | 执行完重试与状态动作后，换下一个候选账号 |
| 返回 | `--return` | 把上游错误直接返回客户端 |

规则采用整条替换，组合约束如下：

- `--disable` 与 `--cooldown` 互斥，`--next_route` 与 `--return` 互斥。
- 既不写 `--next_route` 也不写 `--return` 时默认 `--return`；一个动作都不写会拒绝写入。
- 重试与状态动作可以同时写：先按 `--retry` 重试，全部失败后再执行冷却、停用或换号。
- 重试等待从 `--retry-base` 开始指数翻倍：第 `i` 次等待 `min(base × 2^(i-1), 8s)`，单个客户端请求在一个候选账号上累计最多等待 60 秒，客户端断开即停止。
- 每次重试都是真实的上游调用，各自写入一条请求记录；已经开始向客户端写响应字节的请求不会重试，也不会换号。

### 匹配顺序与内置兜底

用户规则按 `priority` 升序匹配，`priority` 相同按 ID 升序，第一条命中的规则生效。

用户规则都不命中时，进入代码内置兜底：

| 内置规则 | 动作 |
| --- | --- |
| `401` | 停用账号，返回 |
| `402` | 停用账号，换号 |
| `400` 或 `403` 且错误文本命中计费关键词 | 停用账号，换号 |

内置兜底的计费关键词按大小写不敏感的子串匹配，任意一条命中即算：

```text
insufficient credit     no credits             out of credits
credit balance          purchase more credits  payment required
insufficient_quota      余额不足               欠费
额度不足                额度已用完             充值
```

裸 `credit` 与裸 `quota` 故意不列入关键词，避免命中无关报错。

所有规则都未命中时，回落到默认状态码处理。

## 冷却范围与选号

`--cooldown` 带 `--model` 时只冷却该「账号 + 模型」，不影响同一账号的其他模型；不带 `--model` 时写入账号级冷却，让该账号的所有模型一起退出候选。

账号级冷却与账号-模型冷却分开存放，互不影响。

在选号硬过滤阶段，网关会依次排除四类账号：已停用、账号级冷却中、没有声明这个模型、该账号-模型正在冷却中。

`lax route explain` 会列出被排除的账号与具体原因，其中账号级冷却显示为「账号冷却中」。

`--disable` 永远停用整个账号，与规则是否带 `--model` 无关。

### 规则管理与探活联动

```bash
lax route policy ls [--all] [--json]
lax route policy show <id> [--json]
lax route policy add [条件] [动作]
lax route policy set <id> [字段 ...]
lax route policy unset <id> <字段开关 ...>
lax route policy rm <id>
lax route policy enable <id>
lax route policy disable <id>
lax route policy test --status <码> [--message <文本>] [--explain]
```

```bash
# 5xx 与 429：同一账号重试一次（等 500ms），然后返回
lax route policy add --provider myco --status 5xx,429 --retry 1

# 余额不足：停用整个账号并换号
lax route policy add --account acct-a --status 400 \
  --error-contains "insufficient credits" --disable --next_route

# 某个模型的 5xx：只冷却这个账号-模型 30 分钟，然后换号
lax route policy add --model deepseek/deepseek-v4.1-flash --status 5xx --cooldown 30m --next_route

# 预演规则匹配（不请求上游、不写库）
lax route policy test --status 400 --message "You have insufficient credits" \
  --provider myco --explain
```

`lax account test` 与语音容错探测也会执行同一批失败处理规则：计费类 400 命中停用或冷却规则时，账号不会被标成可用；命中规则时 `lax account test` 会多输出一行「命中策略」。

`lax model probe` 的普通对话探活仍按模型级判断，不按规则停用或冷却账号。

## 用 lax route explain 排障

当线上选号结果不符合预期（例如总走 A 账号不走 B 账号、某个账号莫名消失）时，用 `lax route explain` 预演一次选号。

它读取与网关同一份策略快照、权重、统计与额度数据，但**不发上游请求、不写请求记录、也不改冷却状态**。

```bash
lax route explain deepseek/deepseek-v4.1-flash
lax route explain deepseek/deepseek-v4.1-flash --session demo --seed 42
lax route explain deepseek/deepseek-v4.1-flash --json
```

| 参数 | 作用 |
| --- | --- |
| `<模型>` | 必填；可以是别名，输出里显示解析后的真实模型 |
| `--session` | 模拟一个会话键，观察 `--sticky` 粘性效果 |
| `--seed` | `softmax` 的随机种子；相同数据与种子结果一致 |

### 看懂终端表格输出

```text
模型 deepseek/deepseek-v4.1-flash：weighted / 会话 prefer / 来源 模型
额度排序：off / 最低折合 USD：0.00
顺序  账号    权重  样本  成功率  平均延迟  得分   概率
1     acct-a  3     0     50%     -         0.700  -
2     acct-b  1     0     50%     -         0.300  -
最终顺序：acct-a → acct-b
```

| 列 | 含义 |
| --- | --- |
| 顺序 | 本次排出的尝试顺序 |
| 账号 | 账号名 |
| 权重 | 该模型上的有效权重 |
| 样本 | 统计窗口内的账号相关请求数 |
| 成功率 | 平滑后的成功率 |
| 平均延迟 | 成功请求的平均耗时；没有样本时显示 `-` |
| 得分 | 综合评分 |
| 概率 | `softmax` 抽中的概率；非 `softmax` 策略显示 `-` |

被排除的账号会在表格下方单独列一行：

```text
排除：acct-c（正在冷却）；acct-d（没有声明这个模型）；acct-e（额度：折合余额 0.2 USD 低于最低阈值 1 USD）
```

额度过滤造成的排除原因以「额度：」开头，便于与停用、无模型、冷却区分。

## 预演输出中的额度列

只要至少一个候选账号有额度快照，表格就在末尾追加三列（没有快照的账号三列均显示 `-`，不会用 `0` 冒充已知额度）：

```text
顺序  账号    权重  样本  成功率  平均延迟  得分   概率  额度      剩余   到期
1     acct-a  3     0     50%     -         0.700  -     12.5 USD  62.5%  2026-12-01 00:00
2     acct-b  1     0     50%     -         0.300  -     0.2 USD   1.6%   2026-11-16 00:00（临近）
```

`--json` 输出中，有快照的候选会包含 `quota` 对象，`policy.quota_order` 与 `policy.quota_min_usd` 会标明当前选号侧的额度配置。

### 常见排障对照表

| 现象 | 在 `lax route explain` 里看什么 |
| --- | --- |
| 请求总是走同一个账号 | `policy.sticky` 是否为 `prefer` 或 `strict` |
| 期望的账号没被选中 | `排除` 行或 `excluded` 数组里是否有它，以及具体排除原因 |
| `success` 策略没拉开差距 | `attempts` 是否达到 `min_samples`；样本不足时平滑成功率都在 `0.5` 附近 |
| `softmax` 顺序每次不同 | 固定 `--seed` 复现，并检查 `temperature` 与 `explore` |
| 权重没有生效 | `policy.strategy` 是否为 `weighted` 或 `softmax`，以及候选 `weight` 列 |
| 账号被额度排除 | 排除原因是否以「额度：」开头；核对 `quota_order` 与 `quota_min_usd` |
| 设了额度阈值却没排除 | 账号的 `quota.balance_usd` 是否为 `null`；未知余额不会被阈值排除 |
| 额度列没有出现 | 所有候选都没有快照；先运行 `lax quota refresh <账号>` |

预演使用的是调用时刻的快照，不消耗上游额度、也不产生新样本。

真实请求到达时会重新读取最新快照，并且上游刚返回的 429 或 5xx 只有在真实转发后才会触发冷却。
