`lax` 以单个 Go 二进制发布，不依赖 cgo、Node.js 或外部数据库。

默认使用本地 SQLite 文件保存状态。

## 方式一：下载预编译二进制（推荐）

预编译发布包覆盖 Linux 与 macOS 的 `amd64` 和 `arm64` 架构。

<Callout type="info">
Windows 不在预编译发布范围：`lax serve` 与 `lax plugin reload` 依赖 Unix 信号。

在 Windows 上只能自行编译，且部分信号相关功能不可用。
</Callout>

1. 从 [GitHub Releases](https://github.com/sumwai/lax/releases) 下载对应平台与架构的压缩包及 `checksums.txt`。
2. 核对校验和并解压，将 `lax` 放进 `PATH` 覆盖的目录（如 `/usr/local/bin`）：

```bash
sha256sum -c checksums.txt
tar -xzf lax_*.tar.gz
sudo install -m 0755 lax /usr/local/bin/lax
```

3. 验证版本号，输出应与发布 tag 一致（例如 tag 为 `v0.2.1` 时输出 `lax 0.2.1`）：

```bash
lax version
```

## 方式二：从源码编译

需要本地已安装 Go 工具链。在源码仓库根目录执行：

```bash
make check    # 运行 go vet + go test + go build
make build    # 生成带版本号的 ./lax
./lax version
```

`make build` 通过 `git describe --tags --match 'v*'` 自动注入版本号。

若直接使用 `go build`，产物也可运行，但 `lax version` 会显示源码默认值 `0.1.0-dev`。

## 初始化配置与数据目录

首次部署时执行初始化命令：

```bash
lax init
```

该命令会在本地生成三个核心文件：

| 路径 | 职责 |
| --- | --- |
| `$XDG_CONFIG_HOME/lax/config.json` | 网关监听地址、数据库路径与存储驱动配置 |
| `$XDG_DATA_HOME/lax/lax.db` | 供应商、账号、模型目录、选号策略与请求日志 |
| `$XDG_DATA_HOME/lax/secret.key` | 用于加密上游凭据的本地密钥（权限 `0600`） |

重复执行 `lax init` 不会覆盖已有配置。

需要重置配置文件时可使用 `lax init --force`，该参数只重写 `config.json`，不会清空数据库与密钥。

<Callout type="warn">
请妥善保管 `secret.key`。  
备份或迁移主机时，必须将 `config.json`、`lax.db`、`secret.key` 与插件目录一并迁移；  
丢失 `secret.key` 将导致已入库的上游 `API Key` 无法解密。
</Callout>

## 环境变量与路径覆盖

`lax` 按 XDG 规范解析默认目录，可通过环境变量或全局参数覆盖：

| 变量 / 参数 | 作用 | 默认值 / 说明 |
| --- | --- | --- |
| `XDG_CONFIG_HOME` | 配置文件根目录 | 未设置时取 `~/.config`，配置位于 `~/.config/lax/config.json` |
| `XDG_DATA_HOME` | 数据与密钥根目录 | 未设置时取 `~/.local/share`，数据位于 `~/.local/share/lax` |
| `LAX_KEY` | 传入上游 `API Key` | `lax account add` / `set` 省略 `--key` 时从此变量读取，避免明文留在 shell 历史 |
| `--config <路径>` | 临时指定配置文件 | 全局参数，写在子命令前后都生效 |
| `--db <路径>` | 临时指定数据库文件 | 全局参数，写在子命令前后都生效 |

多套环境隔离示例：

```bash
lax --config /path/to/config.json --db /path/to/lax.db serve
lax account ls --config /path/to/config.json --db /path/to/lax.db
```

## 检查本机环境

初始化完成后，运行自检确认配置文件、数据目录权限、加密密钥、端口可用性与数据库状态：

```bash
lax doctor
```

端口检查项会尝试绑定配置中的监听地址。

如果 `lax serve` 正在运行，该项会提示端口已被占用，属于正常现象。

## 可选：切换外部数据库

默认使用内置 SQLite。

仅当需要多进程共享同一份网关状态时，才需在 `config.json` 中切换为 PostgreSQL 或 MySQL：

```json
{
  "db": "/path/to/lax.db",
  "driver": "postgres",
  "dsn": "postgres://user:pass@127.0.0.1:5432/lax?sslmode=disable"
}
```

- `driver`：支持 `sqlite`、`postgres` 或 `mysql`。
- `dsn`：非空时优先使用该连接串，此时忽略 `db` 字段。
- `db`：SQLite 数据库文件路径。

数据库表结构会在程序启动或初始化时自动创建与迁移，不需要手工执行建表语句。

## 凭据加密边界

上游 `API Key` 在入库前使用 `secret.key` 进行 AES-256-GCM 加密。

该机制用于防止数据库备份文件、日志或误传数据库造成的凭据泄漏，无法防御同一台主机上以相同系统用户身份运行的进程直接读取 `secret.key`。
