---
title: 常见问题
description: 客户端接入失败的检查顺序
---

先确认入口返回的状态码，再按客户端类型检查 base URL、token 头与模型名。

## 状态码

| 现象 | 先检查 |
| --- | --- |
| 401 | token 是否完整，以及是否放进了当前客户端使用的那一种头 |
| 404 | base URL 是否多了或少了 `/v1`；模型名是否在 `/v1/models` 里 |
| 400，提示模型不存在 | 客户端写的名字不在模型清单里；用 `/v1/models` 核对 |
| 503 | 入口没有可用候选账号；稍后重试或联系入口管理员 |
| 流式没有输出 | 客户端与入站协议是否匹配；先用非流式请求验证同一模型 |

## base URL

| 客户端 | base URL |
| --- | --- |
| Claude Code、Anthropic SDK | `https://larkax.com` |
| Codex、OpenAI SDK | `https://larkax.com/v1` |
| Gemini SDK | `https://larkax.com` |

## 请求头

| 客户端 | 请求头 |
| --- | --- |
| OpenAI SDK、Codex | `Authorization: Bearer <token>` |
| Claude Code、Anthropic SDK | `x-api-key: <token>` 或 `Authorization: Bearer <token>` |
| Gemini SDK | `x-goog-api-key: <token>` |

## 模型清单

```bash
curl -s https://larkax.com/v1/models \
  -H 'Authorization: Bearer <token>'
```

两个只读接口不写请求记录，也不影响冷却与选号。停用账号提供的模型不会出现在清单里；冷却中的模型仍会出现。
