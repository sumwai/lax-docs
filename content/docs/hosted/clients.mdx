所有客户端都连接同一个网关地址。larkax 不修改客户端自己的配置文件；需要手动把 base URL、鉴权头与模型名指过来。

## 地址与鉴权

| 项目 | 值 |
| --- | --- |
| 网关地址 | `https://larkax.com` |
| 鉴权 | `Authorization: Bearer <token>`、`x-api-key: <token>` 或 `x-goog-api-key: <token>` |
| 客户端 key | 向网关管理员取得的 token |
| 模型名 | 由入口管理员提供，或从 `/v1/models` 查询 |

入站协议由路径决定。请求按客户端习惯带三种 token 头之一，OpenAI 兼容客户端通常用 `Authorization: Bearer <token>`：

| 客户端类型 | 路径前缀 |
| --- | --- |
| anthropic | `/v1/messages` |
| openai-chat | `/v1/chat/completions` |
| openai-responses | `/v1/responses` |
| gemini | `/v1beta/models/{model}:generateContent` |
| openai-embeddings | `/v1/embeddings` 或 gemini 的 `:embedContent` |
| systemone | `/v1/systemone` |
| openai-speech | `/v1/audio/speech` |
| openai-transcriptions | `/v1/audio/transcriptions` |

## Claude Code

```bash
export ANTHROPIC_BASE_URL=https://larkax.com
export ANTHROPIC_AUTH_TOKEN=<token>
export ANTHROPIC_MODEL=deepseek-v4-pro
claude
```

Claude Code 说 anthropic 协议，网关按这个账号的有效出站协议转换或直通。

## Codex

Codex 使用 openai-responses 协议，base URL 要包含 `/v1`：

```toml
# ~/.codex/config.toml
model = "gpt-5.1"
model_provider = "larkax"

[model_providers.larkax]
name = "larkax"
base_url = "https://larkax.com/v1"
env_key = "LARKAX_API_KEY"
```

```bash
export LARKAX_API_KEY=<token>
codex
```

模型名取 `/v1/models` 返回的一项。上游只提供 openai-chat 时，入口会把 responses 请求转到 chat。

## OpenAI SDK

Python：

```python
from openai import OpenAI

client = OpenAI(base_url="https://larkax.com/v1", api_key="<token>")
resp = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "hello"}],
)
print(resp.choices[0].message.content)
```

Node.js：

```js
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "https://larkax.com/v1", apiKey: "<token>" });
const resp = await client.chat.completions.create({
  model: "deepseek-v4-pro",
  messages: [{ role: "user", content: "hello" }],
});
```

## Anthropic SDK

```python
from anthropic import Anthropic

client = Anthropic(base_url="https://larkax.com", api_key="<token>")
msg = client.messages.create(
    model="claude-sonnet",
    max_tokens=256,
    messages=[{"role": "user", "content": "hello"}],
)
```

Anthropic SDK 默认拼 `/v1/messages`，因此 base URL 不带 `/v1`。

## Gemini SDK

gemini 的模型名在 URL 路径里，不在请求体里。网关接受原生 `generateContent` 与 `streamGenerateContent` 路径。

```python
from google import genai

client = genai.Client(
    api_key="<token>",
    http_options={"base_url": "https://larkax.com"},
)
resp = client.models.generate_content(
    model="gemini-2.5-pro",
    contents="hello",
)
```

如果客户端不接受自定义 base URL，也可以直接用 HTTP：

```bash
curl -s https://larkax.com/v1beta/models/gemini-2.5-pro:generateContent \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"contents":[{"parts":[{"text":"hello"}]}]}'
```

## 发现模型

不知道有哪些模型名可用时问网关：

```bash
curl -s https://larkax.com/v1/models \
  -H 'Authorization: Bearer <token>'
curl -s https://larkax.com/v1/models/deepseek-v4-pro \
  -H 'Authorization: Bearer <token>'
```

两个接口只读、只收 GET，不写请求记录，也不影响冷却与选号。停用账号提供的模型不会出现在清单里；冷却中的模型仍会出现。

## 常见接入问题

| 现象 | 先检查 |
| --- | --- |
| 401 | 检查 token 是否填对，以及是否放进了当前客户端使用的那一种头 |
| 404 | 路径是否多了或少了 `/v1`；模型名是否在 `/v1/models` 里 |
| 400，提示模型不存在 | 客户端写的名字不在模型清单里；用 `/v1/models` 核对 |
| 503 | 入口没有可用候选账号；稍后重试或联系入口管理员 |
| 流式没有输出 | 客户端与入站协议是否匹配；先用非流式请求验证同一模型 |
