---
title: 常见问题
description: 启动、模型、账号、协议与用量的高频问题
---

## 网关起不来

先看端口是否被占用：

```bash
lax doctor
```

端口项失败时，换一个地址：

```bash
lax serve --addr 127.0.0.1:4568
```

如果提示“尚未初始化”，运行 `lax init`。如果提示“数据库不存在”，检查 `--db` 或配置里的路径。

## 客户端报模型不存在

1. 用 `lax model ls` 确认模型名；
2. 确认提供它的账号已启用；
3. 确认模型在某个账号上探活通过；
4. 如果客户端写的是别名，用 `lax model alias ls` 看是否能解析。

同步过不代表能用。`model sync` 只把名字写进目录；只有 `model probe` 或 `model add` 才判定可达性。

## 请求持续失败并进入冷却

```bash
lax log tail -n 20
lax route explain <模型>
```

冷却按账号 + 模型记录。429 从 500 毫秒起，5xx 从 10 秒起，连接层失败从 2 秒起，连续失败会翻倍，上限 30 分钟。

如果所有候选都在冷却，网关返回 503。等冷却结束，或调整候选账号。

## 上游 401

账号会被停用。换 key：

```bash
lax account set <账号> --key <新 key>
```

换 key 会清掉冷却、失败次数并重新启用账号，不需要删除重建。

## 上游 403

403 通常是套餐、模型权限或区域限制。lax 不停用账号、不冷却，也不换号，把上游原话返回。先确认这个账号是否真的有这个模型的权限。

## 同一个账号的其它模型也被限流了吗

不会。冷却按账号 + 模型隔离。一个模型 429 不影响同账号的其它模型。

## 为什么有两个账号，请求只走一个

默认策略是 `priority`，按账号的 `priority` 升序先试第一个。要平均分摊，改用 `rotate` 或 `weighted`；要看会话粘性是否把请求固定到同一个账号。

## 为什么 400 不换号

400 通常是请求本身有问题：模型名错、参数不合法、协议不相通。换账号重发同一条错误请求只会重复失败，因此直接返回。

## 流式请求中断后为什么不重试

已经向客户端写出字节后，无法撤回半截响应。重试会把两段响应拼在一起，因此记录失败但不换号。

## 用量里为什么有 0 花费

两种可能：价格确实填了 0，或这一组请求未定价。未定价显示“未定价”，`--json` 里 `cost` 为 `null`；免费显示 `0.00`。

## 探活费用能排除吗

目前不能按请求类型单独排除。探活请求也写请求记录并进入用量汇总。

## 能放到公网吗

自部署时，网关本身不校验入站凭据，默认只监听回环地址。对外提供服务前必须加认证与 TLS，并限制访问来源；不要把 `127.0.0.1:4567` 直接映射到公网。`https://larkax.com` 已在入口加了 Bearer token 鉴权与 TLS。

## Windows 支持吗

发布包不覆盖 Windows。`serve` 与 `plugin reload` 依赖 Unix 信号；在 Windows 上只能自行构建并预期部分功能不可用。

## 插件装完不生效

1. `lax plugin ls` 看状态；
2. `lax plugin doctor` 看包与沙箱；
3. 正在运行的网关执行 `lax plugin reload`，或重启 `serve`；
4. 检查账号是否被插件删除时的停用状态影响，需要 `account enable`。

## 换机器怎么搬

配置、数据库、`secret.key` 与 `plugins/` 一起搬。只搬数据库会导致旧凭据无法解密，插件包也会缺失。
