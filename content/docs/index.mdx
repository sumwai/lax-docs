---
title: larkax
description: 一个地址接入多家上游、多种协议
---

larkax 是模型网关。默认入口是 `https://larkax.com`，客户端把各家的 SDK 指过来就能使用；也可以在自己的主机上部署同一套网关。

它解决的是一个日常问题：Claude Code 说 anthropic，Codex 说 openai-responses，普通 OpenAI SDK 说 openai-chat，Google SDK 说 gemini。没有网关时，每一种客户端都要单独配置上游地址、凭据与模型名。larkax 把这些配置集中在一个入口后面，客户端换协议、换上游、换账号都不用改代码。

```text
Claude Code ─┐
Codex ───────┼─→ https://larkax.com ─→ 供应商 A / 账号 A1
OpenAI SDK ──┤                             供应商 A / 账号 A2
Gemini SDK ──┘                             供应商 B / 账号 B1
```

## 它是什么

| 特性 | 说明 |
| --- | --- |
| 默认入口 | 客户端连接 `https://larkax.com`，用 Bearer token 鉴权 |
| 多协议 | 八条线协议：anthropic、openai-chat、openai-responses、gemini、systemone、openai-embeddings、openai-speech、openai-transcriptions |
| 协议转换 | 四条对话协议任意进入、任意出站，共十六种组合；流式、工具调用与思考内容都在转换范围内 |
| 账号池 | 同一供应商可加多个账号，按主备、轮转、权重、成功率或 softmax 选号 |
| 模型治理 | 从上游同步清单，再逐个探活；只有探活通过的模型参与选号 |
| 插件 | 声明式映射或 `moejs` 沙箱插件，用来接入特殊上游形状，尤其是语音 |
| 可观测 | 每次尝试写一条请求记录，按账号、模型、日期汇总用量并估算花费 |

## 它不是什么

- 不是多租户服务：没有用户、充值、额度与网页后台。
- 入口鉴权只区分能否访问，不区分不同用户的数据与配额。
- 不是必须自部署：默认直接连接 `larkax.com`，自部署只是可选项。
- 不支持订阅账号登录：只接受粘贴 API key，不处理浏览器 OAuth 与 token 刷新。
- 不逆向上游接口：只按上游公开的 HTTP 协议转发。

## 第一条请求

```bash
curl -s https://larkax.com/v1/chat/completions \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-v4-pro","messages":[{"role":"user","content":"hi"}]}'
```

token 由入口管理员提供。完整步骤见[客户端接入](/docs/clients)。

自部署时，先安装并初始化，再添加自己的上游账号、同步并探活模型，最后启动 `lax serve`。步骤见[自部署](/docs/self-hosted)。
