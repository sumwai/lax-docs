---
title: 概览
description: 本机上的模型网关，一个地址接入五种线协议的客户端
---

lax 是运行在本机的模型网关。多家供应商的 API key 保存在本地文件中，客户端统一连接 `http://127.0.0.1:4567`。

客户端只需要这一个地址。账号选择、协议转换与用量记录都由 lax 完成。

客户端本身通常只支持一种线协议，为此需要为每一种客户端单独维护一套账号与地址。

lax 把这套配置收敛到单一入口：任意一种协议的客户端接入后，都按账号实际支持的协议转发。

入站与出站协议相同时报文原样直通，不同则经统一表示转换。

## 几个反复出现的说法

后面几组文档反复用到下面这些说法，先给出定义：

| 说法 | 指什么 |
| --- | --- |
| 账号 | 一份上游凭据，连同它的地址、出站协议与可用模型；同一供应商可以添加多个账号 |
| 选号 | 每个请求进来后挑一个账号转发，依据是请求里的模型名、账号的 `--priority` 与冷却状态 |
| 冷却 | 账号刚失败过、被暂时移出候选的一段时间；冷却中的账号仍出现在清单里，但不接新请求 |
| 模型清单 | 上游公布的模型名列表，用 `model sync` 拉取；同步只说明上游有这个名字，不代表打得通 |
| 探测 | 真向上游发一条请求（对话模型是 `max_tokens=1`，决策模型是最小决策请求），确认某个模型打得通；只有探测通过的模型才参与选号 |
| 直通 | 入站与出站协议相同时，报文原样带到上游，不做字段转换 |
| 映射表 | 跨协议转换时定义「哪个字段搬到哪里」的那张表，表外的字段不搬 |
| 决策请求 | systemone 协议下的一次请求：一份材料与一组问题，返回每个问题的答案与概率，不出文本 |

## 功能范围

| 能力 | 说明 |
| --- | --- |
| 五种入站协议 | anthropic、openai-chat、openai-responses、gemini、systemone，按路径区分，可同时启用 |
| 五种出站协议 | 同上，归属在模型与供应商上 |
| 协议转换 | 前四条之间的十六种入站 × 出站组合，流式与非流式均支持，含工具调用 |
| 决策请求 | `POST /v1/systemone` 发一份材料与一组问题，返回每个问题的答案与概率；不参与跨协议转换 |
| 账号池 | 多个凭据轮转，按优先级与冷却状态选号，失败时自动切换 |
| 模型管理 | 从上游同步模型清单并逐个探测，仅探测通过的模型进入候选集 |
| 用量记录 | 记录每次请求的 token 与估算花费，可按账号、模型、日期汇总 |

## 不提供的功能

- 没有用户、充值、额度体系，只有本机的一份账号池；
- 没有网页后台，所有操作走命令行；
- 不监听回环地址之外的端口，也不校验入站凭据，因此不适合对外提供服务；
- 不改写客户端自身的配置文件，需要手动把客户端的 base URL 指过来。

## 快速上手

```bash
make build                                             # 编译出单文件 ./lax
./lax init                                             # 创建配置、数据库与加密密钥
./lax account add ds --provider deepseek --key sk-xxx  # ds 是自取的账号名，后续命令用它指向这个账号
./lax model sync --account ds                          # 拉取该账号的上游模型清单
./lax model probe --account ds                         # 逐个探测，只有通过的模型能接请求
./lax serve                                            # 前台启动网关，监听 127.0.0.1:4567
```

随后将客户端的 base URL 指向 `http://127.0.0.1:4567`。完整步骤与每步的失败提示见[快速开始](/docs/quickstart)。
