---
title: lax
description: 本机上的模型总机：一个地址接入多家上游、多种协议
---

lax 是运行在本机的模型网关。它把多家上游的 API key、模型清单与选号策略收在一台机器上，客户端只连接一个地址。

它解决的是一个日常问题：Claude Code 说 anthropic，Codex 说 openai-responses，普通 OpenAI SDK 说 openai-chat，Google SDK 说 gemini。没有网关时，每一种客户端都要单独配置上游地址、凭据与模型名。lax 把这些配置集中在本机，客户端换协议、换上游、换账号都不用改代码。

```text
Claude Code ─┐
Codex ───────┼─→ http://127.0.0.1:4567 ─→ 供应商 A / 账号 A1
OpenAI SDK ──┤                             供应商 A / 账号 A2
Gemini SDK ──┘                             供应商 B / 账号 B1
```

## 它是什么

| 特性 | 说明 |
| --- | --- |
| 本机优先 | 默认只监听 `127.0.0.1:4567`，不校验入站凭据，适合单人单机 |
| 多协议 | 八条线协议：anthropic、openai-chat、openai-responses、gemini、systemone、openai-embeddings、openai-speech、openai-transcriptions |
| 协议转换 | 四条对话协议任意进入、任意出站，共十六种组合；流式、工具调用与思考内容都在转换范围内 |
| 账号池 | 同一供应商可加多个账号，按主备、轮转、权重、成功率或 softmax 选号 |
| 模型治理 | 从上游同步清单，再逐个探活；只有探活通过的模型参与选号 |
| 插件 | 声明式映射或 `moejs` 沙箱插件，用来接入特殊上游形状，尤其是语音 |
| 可观测 | 每次尝试写一条请求记录，按账号、模型、日期汇总用量并估算花费 |

## 它不是什么

- 不是多租户服务：没有用户、充值、额度与网页后台。
- 不是云端代理：数据、密钥与请求记录都在本机。
- 不提供公网鉴权：默认只绑回环地址；要放到内网或公网，前面必须自己加认证与 TLS。
- 不支持订阅账号登录：只接受粘贴 API key，不处理浏览器 OAuth 与 token 刷新。
- 不逆向上游接口：只按上游公开的 HTTP 协议转发。

## 一条最短路径

```bash
make build                                             # 生成单文件 ./lax
./lax init                                             # 配置、数据库、密钥
./lax account add ds --provider deepseek --key sk-xxx  # 添加一个账号
./lax model sync --account ds                          # 拉上游模型清单
./lax model probe --account ds                         # 探活，只有通过的进入选号
./lax serve                                            # 前台启动网关
```

然后把客户端的 base URL 指向 `http://127.0.0.1:4567`。完整步骤见[快速开始](/docs/start/quickstart)，各客户端的配置见[客户端接入](/docs/start/clients)。
