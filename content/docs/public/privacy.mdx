title: 数据与隐私
description: 公开网关记录的数据范围，以及 API Key 的保管方式
---

公开网关 [https://larkax.com](https://larkax.com) 只负责请求转发与线路调度，不是对话存储服务。

了解网关记录与不记录的内容，有助于判断哪些数据适合通过网关发送。

## 记录的内容

每次向上游发起尝试时，网关会写入一条请求元数据记录，用于统计用量与排查故障：

| 字段 | 内容 |
| --- | --- |
| 时间 | 请求发生的时间 |
| 协议 | 入站协议与实际转发使用的协议 |
| 模型 | 客户端请求的模型名与实际命中的模型名 |
| 线路标识 | 网关内部使用的线路名称 |
| 状态与耗时 | HTTP 状态码、是否成功、请求耗时 |
| 用量 | 输入、输出、思考与缓存读写 token 数量 |
| 错误摘要 | 经过凭据脱敏后的失败原因摘要 |

## 不记录的内容

网关只向数据库写入上述转发结果与统计计数，**不保存**请求正文、响应正文、请求头、响应头、上游凭据、网关 `API Key`，以及音频文件或向量数据。

需要注意，上游模型供应商仍会按照各自的隐私政策处理收到的请求内容，这部分策略由对应供应商决定。

## 管理员可见范围

网关管理员可以查看请求发生的时间、模型、线路标识、状态码、耗时、token 用量与脱敏后的错误摘要，无法在网关记录中查看完整的对话内容、代码片段或请求头。

错误摘要中可能包含上游返回的简短错误提示，但不包含完整请求报文。

## API Key 保管建议

- 将 `API Key` 存放在环境变量、系统密钥环或本地客户端配置文件中，不要提交到代码仓库。
- 避免将 `API Key` 写入前端代码、屏幕截图、公开日志或 URL 查询参数。
- 怀疑凭据泄露时，请立即联系网关管理员更换或停用对应 `API Key`。
- 若管理员为不同使用者发放了独立 `API Key`，请妥善各自保管，避免共用或转交。

## 适用数据范围

网关适合转发日常对话、代码片段、工具调用参数与公开技术资料。

若涉及个人隐私信息、未脱敏的生产密钥、受监管数据或不可离开内部网络的内容，请先向网关管理员确认合规要求与上游供应商的数据政策。
