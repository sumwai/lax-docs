---
title: 数据与隐私
description: 公开入口记录哪些数据、不记录哪些数据，以及 token 应该怎样保管
---

公开入口是转发层，不是对话存储服务。理解它记录什么，可以判断哪些内容适合发到入口。

## 记录什么

每次上游尝试写一条请求记录，包含：

| 字段 | 内容 |
| --- | --- |
| 时间 | 请求发生的时间 |
| 协议 | 入站协议与出站协议 |
| 模型 | 客户端请求的模型名与实际使用的模型名 |
| 账号 | 入口内部的账号名 |
| 状态与耗时 | HTTP 状态码、是否成功、耗时 |
| 用量 | 输入、输出、思考与缓存读写 token |
| 错误摘要 | 失败原因，经过凭据清洗 |

## 不记录什么

- 不保存请求正文与响应正文；
- 不保存请求头与响应头；
- 不保存上游凭据与入口 token；
- 不保存音频文件或向量。

写入数据库的是转发结果与计数，不是对话内容。上游供应商仍会按自己的政策处理收到的请求，这部分不受入口控制。

## token 怎么保管

- 把 token 放在环境变量、系统密钥环或客户端自己的配置里，不要提交到仓库。
- 不要把 token 写进前端代码、截图、日志或 URL。
- 怀疑泄露时立即联系入口管理员处理；token 的更换与停用方式由管理员决定。
- 如果管理员为不同使用者发放不同 token，按人保管，避免共用或转交。

## 管理员能看到什么

入口管理员可以查看请求记录、模型、账号、状态、耗时、token 用量与错误摘要，也可以看到请求发生的时间。请求记录不保存完整的请求正文、响应正文与请求头；错误摘要可能包含上游返回的错误文本，但不是完整报文。

## 适合发送的内容

入口适合发送普通对话、代码片段、工具调用参数与公开资料。涉及个人隐私、未脱敏密钥、受监管数据或不能离开内部网络的内容，应先确认管理员与上游供应商的数据政策。
