本页只处理客户端一侧的接入失败：base URL、请求头、模型名与流式设置。判断状态码含义先看[错误与限制](/errors#状态码)；401 的凭据与请求头写法先看[凭据与请求头](/auth)。网关启动、模型同步与账号问题不在本页，见[常见问题](/self-hosted/faq)。

## 状态码

| 现象 | 先检查 |
| --- | --- |
| 401 | API Key 是否完整，以及是否放进了当前客户端使用的那一种头 |
| 404 | base URL 是否多了或少了 `/v1`；模型名是否在 `/v1/models` 里 |
| 400，提示模型不存在 | 客户端写的名字不在模型清单里；用 `/v1/models` 核对 |
| 503 | 入口没有可用候选账号；稍后重试或联系入口管理员 |
| 流式没有输出 | 客户端与入站协议是否匹配；先用非流式请求验证同一模型 |

## base URL

## 请求头

三种请求头的完整写法见[三种请求头](/auth#三种请求头)。

## 模型清单

```bash
curl -s https://larkax.com/v1/models \
  -H 'Authorization: Bearer <API Key>'
```

两个只读接口不写请求记录，也不影响冷却与选号。停用账号提供的模型不会出现在清单里；冷却中的模型仍会出现。
