入口尽量用状态码说明问题出在哪一层。先看状态码，再检查 API Key、路径与模型名，通常就能定位。

## 状态码

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 400 | 请求不合法：模型名、协议字段或路径参数有问题 | 按错误文案修改请求，不要原样重试 |
| 401 | API Key 缺失、错误，或没有放在当前协议使用的头里 | 检查 API Key 与请求头 |
| 403 | 上游拒绝权限或套餐 | 模型或账号没有权限，联系入口管理员 |
| 404 | 模型名不在清单，或路径不存在 | 用 `/v1/models` 核对模型名与路径 |
| 405 | 路径存在但方法不对 | 对话路径用 `POST`，模型清单用 `GET` |
| 413 | 请求体超过上限 | 缩小输入、附件或音频 |
| 429 | 上游限流 | 退避后重试；入口会自动换账号 |
| 500 | 入口内部错误，例如数据库或选号策略读取失败 | 稍后重试，持续失败时联系管理员 |
| 502 | 没有拿到上游响应，或上游返回无法处理的响应 | 稍后重试 |
| 503 | 模型有提供者，但本次候选都失败或在冷却 | 稍后重试，或换一个模型 |

错误体的形状由入站协议决定。OpenAI 路径是 `{"error":{...}}`，Anthropic 是 `{"type":"error","error":{...}}`，Gemini 是 `{"error":{"code":...,"status":...}}`。完整对照见[错误响应](/docs/self-hosted/gateway/errors)。

## 401 先检查什么

| 客户端 | 正确写法 |
| --- | --- |
| OpenAI SDK、Codex、curl | `Authorization: Bearer <API Key>` |
| Claude Code、Anthropic SDK | `x-api-key: <API Key>` 或 `Authorization: Bearer <API Key>` |
| Gemini SDK | `x-goog-api-key: <API Key>` |

同一个 API Key 可以放在三种头里，但不要写进 URL 查询参数。浏览器直接打开 `https://larkax.com` 时走 Basic 认证，用户名与密码由管理员提供，和 API Key 不是同一种凭据。

## 请求体上限

| 路径 | 上限 |
| --- | --- |
| 四条对话路径 | 32 MiB |
| 向量化 | 32 MiB |
| 语音两条路径 | 32 MiB |
| systemone | 8 MiB |

超过上限返回 413，不会截断后继续转发。音频还要受上游自己的大小限制约束。

## 重试

- 429、500、502、503 可以退避重试；入口已经在一次请求内尝试过其它候选账号。
- 400、401、403、404、405、413 不要原样重试，先修正请求或凭据。
- 流式请求已经输出内容后失败，不要拼接重试结果；从新请求重新生成。

同一条请求可能在上游尝试多个账号，每次尝试都会写一条记录。客户端只看到最终响应，管理员在用量与日志里能看到失败尝试。

## 入口不提供的功能

| 功能 | 现状 |
| --- | --- |
| 自助注册、登录、控制台 | 不提供，API Key 由管理员发放 |
| 余额、充值、按用户配额页面 | 不提供，入口本身没有多租户计费 |
| 对话或文件存储 | 不提供，只转发请求 |
| 订阅账号 OAuth 登录 | 不支持，只接受 API Key |
| 按用户隔离日志 | 不提供，管理员能看到入口的请求记录 |
