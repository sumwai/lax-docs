公开入口按路径区分协议。客户端用哪种 SDK，就请求对应的路径；网关负责把请求交给合适的账号，必要时转换成上游能理解的协议。

## 四条对话路径

| 路径 | 协议 | 典型客户端 |
| --- | --- | --- |
| `POST /v1/chat/completions` | openai-chat | OpenAI SDK、curl |
| `POST /v1/responses` | openai-responses | Codex |
| `POST /v1/messages` | anthropic | Claude Code、Anthropic SDK |
| `POST /v1beta/models/{model}:generateContent` | gemini | Google Gen AI SDK |

四条路径可以指向同一个模型。客户端说 anthropic，而模型在上游走 openai-chat 时，入口会转换消息、工具与用量字段；反过来也一样。协议各自独有的字段不会跨协议搬运，细节见[协议转换](/docs/self-hosted/gateway/conversion)。

## 用 OpenAI SDK

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://larkax.com/v1",
    api_key="<token>",
)

resp = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "hello"}],
)
print(resp.choices[0].message.content)
```

base URL 要包含 `/v1`，SDK 会自己拼接 `/chat/completions`。写成 `https://larkax.com` 时，请求会落到根路径并返回 401 或 404。

## 用 Anthropic SDK

```python
from anthropic import Anthropic

client = Anthropic(
    base_url="https://larkax.com",
    api_key="<token>",
)

msg = client.messages.create(
    model="deepseek-v4-pro",
    max_tokens=256,
    messages=[{"role": "user", "content": "hello"}],
)
```

Anthropic SDK 的 base URL 不带 `/v1`，SDK 会拼成 `/v1/messages`。`max_tokens` 是这条协议的必填项。

## 流式输出

对话协议支持 SSE 流式。OpenAI SDK 用 `stream=True`，Anthropic SDK 用 `stream=True` 并迭代事件，Gemini 走 `:streamGenerateContent`。

```bash
curl -N https://larkax.com/v1/chat/completions \
  -H "Authorization: Bearer $LARKAX_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "deepseek-v4-pro",
    "stream": true,
    "messages": [{"role": "user", "content": "数到五"}]
  }'
```

流式请求一旦开始向客户端写出内容，中途失败不会换账号重试，也不会把同一段回答再发一遍。需要自动重试时，请在自己的客户端里按完整请求重试。

## 工具调用

四条对话协议之间的工具定义、工具调用与工具结果会随消息一起转换。某一家协议独有的工具类型与字段不保证跨协议搬运；请求前先在目标上游模型上验证一次。

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询城市天气",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        },
    },
}]

resp = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "北京天气如何？"}],
    tools=tools,
)
```

## 会话粘性与多轮对话

同一个模型有多个上游账号时，入口默认按选号策略选择。需要让同一条对话尽量固定到同一个账号，可以带一个稳定的会话标识：

```bash
-H 'x-lax-session: conversation-42'
```

也可以在支持 `metadata` 的请求体里设置 `metadata.user_id`。`x-lax-session` 只用于选号与供应商附加头，不会透传到上游。会话粘性只是尽量固定，不保证账号永远可用。

## 向量化、决策与语音

入口还提供三类非对话接口：

| 用途 | 路径 | 说明 |
| --- | --- | --- |
| 向量化 | `POST /v1/embeddings` | OpenAI 形状，只做同协议直通 |
| Gemini 向量化 | `POST /v1beta/models/{model}:embedContent` | 模型名在路径里 |
| 决策请求 | `POST /v1/systemone` | TypeSafe System One 形状，只与自身互通 |
| 语音合成 | `POST /v1/audio/speech` | 需要模型声明 `speech` 能力 |
| 语音转写 | `POST /v1/audio/transcriptions` | 需要模型声明 `transcription` 能力 |

这些接口是否可用取决于管理员是否为模型声明能力与路由。先用模型清单确认，再按[线协议](/docs/self-hosted/gateway/protocols)里的请求形状调用。

## 模型名与别名

请求里的 `model` 使用 `/v1/models` 返回的名字。入口可能配置了别名，客户端写别名也能解析到真实模型；返回里的模型名可能因此不同。
