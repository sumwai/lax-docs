---
title: 请求头
description: 客户端头透传、凭据头生成与供应商附加头的叠加顺序
---

一次上游请求的头由三部分组成：网关自己生成的头、客户端透传的头、供应商声明的附加头。三者有明确优先级。

## 凭据头

默认由入站或出站线协议决定：

| 线协议 | 默认头 |
| --- | --- |
| anthropic | `x-api-key: <key>` |
| gemini | `x-goog-api-key: <key>` |
| 两条 openai 协议 | `Authorization: Bearer <key>` |
| embeddings | `Authorization: Bearer <key>` |
| speech / transcriptions | `Authorization: Bearer <key>` |
| systemone | 按供应商声明或默认推导 |

供应商可以覆盖：

```bash
lax provider set myco --auth-header X-Api-Key --auth-scheme raw
lax provider set myco --auth-header Authorization --auth-scheme bearer
```

`raw` 表示头值就是 key；`bearer` 表示 `Bearer <key>`；`bearer-semicolon` 表示 `Bearer;<key>`。声明之后不再发送协议默认头。

## 客户端头透传

只有白名单里的客户端头会带到上游，避免把客户端的 `Host`、`Cookie` 或 `Authorization` 发错地方。

| 头 | 说明 |
| --- | --- |
| `anthropic-beta` | anthropic 的 beta 功能开关 |
| `anthropic-version` | anthropic API 版本 |
| `openai-beta` | OpenAI beta 功能开关 |
| `openai-organization` | OpenAI 组织 ID |
| `openai-project` | OpenAI 项目 ID |

只有入站协议与有效出站协议相同时才透传。从 anthropic 转到 chat 时，`anthropic-beta` 发给 chat 上游只会换回 400，因此一个头都不带。单条头的值超过 8 KiB 时整条丢弃。

客户端的 `Authorization`、`x-api-key`、`x-goog-api-key`、`Cookie`、逐跳头与 `x-lax-session` 不会透传；凭据由网关按账号注入。

## 供应商附加头

上游除凭据外还要求别的头时，在供应商上声明：

```bash
lax provider header set opencode x-opencode-session '{session}' --protocol openai-chat
lax provider header ls opencode
lax provider header unset opencode x-opencode-session --protocol openai-chat
```

值可以使用三种整值模板：

| 写法 | 展开 |
| --- | --- |
| `{session}` | 本次请求的会话键；没有时每次请求生成一个 UUID |
| `{model}` | 本次请求的模型名；模型列表请求没有模型名时不发这个头 |
| `{env:NAME}` | 环境变量 `NAME` 的值；未设置或为空时不发这个头 |

模板必须占满整个值，不做局部替换。展开结果含回车、换行或 NUL 时不发这个头。

作用范围：

| 参数 | 作用 |
| --- | --- |
| 不给 `--protocol` | 这个供应商的全部上游请求 |
| `--protocol <协议>` | 只加给这条协议对应的路由 |

## 叠加顺序

1. 网关基础头（`Content-Type`、`Accept`、主机等）；
2. 凭据头（供应商声明或协议默认生成）；
3. 客户端白名单头（同名的覆盖凭据默认值，例如 `anthropic-version`）；
4. 供应商附加头（同名的覆盖客户端头）；
5. 插件方言逐请求头（同名时最后生效）。

供应商附加头可以覆盖凭据头；插件方言的逐请求头不能设置凭据、Cookie、逐跳头或 `proxy-*` 等保留头。

## 不进请求记录

请求记录保存协议、模型、账号、状态、token、耗时与错误摘要，不保存请求头与响应头。凭据头本身也不进入任何输出。

## 调试头

手工验证时加 `--debug`，`model call` 会把实际请求地址与上游状态写到 stderr。它不打印凭据头。
