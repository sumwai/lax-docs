---
title: 向量化
description: 两条向量化入站、路由声明与同协议直通
---

向量化没有消息序列：输入一段文本或一组文本，输出一组向量。它不参与对话协议的转换，只做同协议直通。

## 两条入站

| 方法 | 路径 | 协议 |
| --- | --- | --- |
| POST | `/v1/embeddings` | openai-embeddings |
| POST | `/v1beta/models/{model}:embedContent` | gemini 向量化 |

两条都只接受 POST，不支持流式。请求带 `stream` 时返回 400。

## 声明路由

向量化端点是否存在由供应商决定，因此在供应商上声明：

```bash
lax provider set openai embeddings=/v1/embeddings
lax provider add myco --base-url https://api.example.com \
    --embeddings /v1/embeddings \
    --default-protocol embeddings
```

内置的 `openai` 与 `ollama` 已经声明了 `/v1/embeddings`。

模型要能用于这个端点，需要在模型目录里声明 `embedding` 能力：

```bash
lax model capability add text-embedding-3-small --capability embedding
```

## 转发

| 项 | 行为 |
| --- | --- |
| 模型名 | 从请求体读取，用于选号 |
| 出站协议 | 必须是 openai-embeddings 或对应的 gemini 形状 |
| 请求体 | 原样转发 |
| 响应体 | 原样返回 |
| 用量 | 读取上游返回的 token 字段；缺失时不估算 |

## gemini

gemini 的 `:embedContent` 入站与 `:batchEmbedContents` 形状不同。lax 目前只接受单条 `:embedContent`，且要求模型与供应商都声明向量化路由。

## 探活

`model probe` 对只声明 `embedding` 能力的模型会走向量化端点，不会用对话请求去探。对话端点返回 400、而供应商声明了向量化路由时，探活会再试一次向量化端点；2xx 即标为可用。

## 排查

| 现象 | 检查 |
| --- | --- |
| 400 且提示没有声明路由 | `lax provider ls --verbose` 看供应商是否有 openai-embeddings 路由 |
| 400 且提示模型没有能力 | `lax model capability ls` |
| 503 | `lax route explain <模型>` 看候选是否可用 |
| 上游 404 | 路由路径是否对应上游真实的向量化端点 |
