## 前置条件

- Go 1.26 或更新版本，仅用于编译，运行时不依赖 Go
- 一个可用的供应商 API key

数据库使用纯 Go 的 SQLite 实现，无需安装数据库服务，也不依赖 CGO。

## 构建

```bash
make build      # 等价于 go build -o lax ./cmd/lax
./lax --help
```

构建产物为单个可执行文件 `lax`，可复制到其它目录或加入 `PATH`。

下文写作 `./lax`，指当前目录下的这个文件。装进 `PATH` 之后直接写 `lax` 即可。

## 初始化

```bash
./lax init
```

该命令创建配置目录、数据目录与加密密钥，并写入默认配置。三个位置如下：

| 路径 | 内容 |
| --- | --- |
| `$XDG_CONFIG_HOME/lax/config.json` | 监听地址、数据库路径 |
| `$XDG_DATA_HOME/lax/lax.db` | 账号、模型状态、请求记录 |
| `$XDG_DATA_HOME/lax/secret.key` | 加密凭据的密钥 |

`XDG_CONFIG_HOME` 与 `XDG_DATA_HOME` 未设置时按惯例取 `~/.config` 与 `~/.local/share`。

重复执行 `init` 不会覆盖已有的 `config.json`，只补齐缺失的目录、数据库与密钥，因此可以放心再执行一次。

需要重写配置时加 `--force`：它只重写 `config.json`，不动数据库与密钥。

凭据以 AES-256-GCM 加密后入库。该措施用于防范备份文件与日志泄漏，不防范同一台机器上以同一用户身份运行的程序。

## 环境自检

```bash
./lax doctor
```

逐项检查，每行给出 `ok` 或 `fail` 与该项的说明：

| 检查项 | 通过的说明 | 失败时 |
| --- | --- | --- |
| 配置文件 | `config.json` 存在，右侧是它的路径 | 先运行 `lax init` |
| 数据目录可写 | 能在数据目录里创建临时文件 | 检查目录权限与磁盘剩余空间 |
| 加密密钥 | `secret.key` 存在；右侧固定注明应为 `0600`，不校验实际权限 | 先运行 `lax init` |
| 配置解析 | `config.json` 能读出监听地址 | 按报错原文修正该文件里的字段 |
| 端口 | 监听地址可以占用 | 端口被别的进程占用，见[网关无法启动](/docs/faq#网关无法启动) |
| 数据库 | SQLite 能打开并读出账号数 | 文件损坏或路径不可写 |
| 旧数据搬迁 | 只在需要时出现，右侧给出搬迁命令 | 新库为空而旧目录还有数据，按给出的命令搬迁 |

「旧数据搬迁」是条件项：新库是空的、而改名前的目录里还有数据库时才会出现，检查项数因此不固定。

任一项失败时退出码为 1，stderr 给出 `doctor: 2 项检查未通过` 这类信息，数字是失败项数。

按上表逐项处理，全部通过之后再接客户端，可以提前排除多数环境问题。

## 备份与迁移

备份账号与用量记录时，复制配置目录的 `config.json` 与数据目录的 `lax.db`、`secret.key`，共三项。

只复制数据库而不含密钥时，其中的凭据无法解密。账号需要重新添加并填入凭据。

迁移到另一台机器后，先运行一次 `lax doctor`，确认配置解析、端口与数据库三项都通过，再接客户端。

## 从旧版本升级

项目从 `switchboard` 改名为 `lax`，命令名、配置目录、数据目录与环境变量都随之改变：

| 项 | 旧 | 新 |
| --- | --- | --- |
| 命令 | `switchboard` | `lax` |
| 配置目录 | `~/.config/switchboard` | `~/.config/lax` |
| 数据目录 | `~/.local/share/switchboard` | `~/.local/share/lax` |
| 数据库文件 | `switchboard.db` | `lax.db` |
| 环境变量 | `SWITCHBOARD_KEY` | `LAX_KEY` |
| 会话粘性请求头 | `x-switchboard-session` | `x-lax-session` |

数据库与配置不会自动搬迁。新名字下第一次运行 `lax doctor` 时，若新库还是空的而旧目录里仍有数据，环境自检会列出一项失败，并把该执行的 `mv` 命令写在同一行：照它把数据库、密钥与配置文件搬到新位置即可，账号、单价与用量都还在。搬迁之后这一项就不再出现。

只搬数据库而不搬 `secret.key` 时，库里的凭据解不开，账号需要重新录入凭据。
