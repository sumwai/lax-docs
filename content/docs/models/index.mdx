title: 模型
description: 从上游同步模型清单、逐个探测可用性，仅可用模型进入选号
---

模型清单无需手工填写，也无需预先了解上游的返回格式。两条命令分工明确：`model sync` 获取清单，`model probe` 逐个探测。探测指对单个模型真发一条请求，确认这个账号能不能真的用它（哪种协议发哪种请求见[探测可用性](#探测可用性)）。探测通过的模型才写进账号的模型列表。

网关为一次请求挑一个账号发出去，这一步称为选号。选号只看探测结果写成的模型列表，而不是上游给的清单，详见[选号依据](#选号依据)。

命令的参数表、输出列与 `--json` 字段见[模型命令](/docs/cli/model)；客户端写死的模型名可以指向真实模型，见[模型别名](/docs/models/alias)。

## 同步模型清单

```bash
lax model sync                                  # 全部账号各执行一次
lax model sync --provider deepseek --account ds # 仅处理指定账号
lax model sync --account ds --endpoint /v1/models # 临时替换地址，仅影响本次调用
```

清单格式自动识别，三种形状都支持：

| 上游返回的形状 | 处理 |
| --- | --- |
| `{data:[…]}` | 取条目里的模型名 |
| `{models:[…]}` | 同上；gemini 的 `{models:[{"name":"models/…"}]}` 属于这一种 |
| 顶层数组 | 逐个取模型名 |

gemini 的清单会按 `supportedGenerationMethods` 过滤掉不支持 `generateContent` 的条目。名称中的 `models/` 前缀也会去掉。

TypeSafe 的决策模型清单是 `{"models":[{"name":"jev-latest"}]}`，属于上表第二种，`model sync` 直接可用。commandcode 的清单不列决策模型，那边的 `typesafe/jev` 只能用 [`account add --models`](/docs/accounts#添加账号) 手填，接入步骤见[接入决策模型](/docs/providers/paths#接入决策模型systemone)。

分页依据响应里的 `nextPageToken` 逐页获取，每页 `pageSize=1000`，最多 10 页。超过 10 页时报错，并提示改用 `--models` 手填。

同步仅读取清单，不消耗 token。单个账号同步失败不影响其它账号，最终退出码为 1。

## 探测可用性

```bash
lax model probe                                 # 全部账号的全部模型
lax model probe --account ds --limit 5           # 仅探测该账号的前 5 个待探模型
lax model probe --account ds --model deepseek-v4-pro  # 仅探测单个模型
lax model probe --account ds --concurrency 4     # 并发数，缺省 4
lax model probe --account ds --refresh           # 忽略已有结论，全部重新探测
lax model probe --account ds --max-age 6h        # 已有结论的新鲜期，缺省 24h
```

每次探测对应上游一条真实请求，会消耗少量 token。请求哪一种按协议定：

| 模型的出站协议 | 探活请求 |
| --- | --- |
| anthropic、openai-chat、openai-responses、gemini | `max_tokens=1` 的对话请求 |
| systemone | 最小决策请求：`state` 为 `ping`，一个问题（`noul` 型）问一句话在不在 |

systemone 用决策请求探活，不能用对话请求：决策端点不认 `messages`，发对话请求只会换回 404，把「模型可用」误判成「模型不存在」。

结果写成账号对这个模型的可达性（`access`）：

| 可达性 | 触发条件 | `--max-age` 窗口内 | 能进候选池 |
| --- | --- | --- | --- |
| `allowed` | 探测通过 | 跳过重探 | 是 |
| `forbidden` | 上游返回 403 等权限错误 | 跳过重探 | 否 |
| `missing` | 上游返回 404 | 跳过重探 | 否 |
| `error` | 其它错误（含 401，账号同时被停用） | 每次都重探 | 否 |
| 无记录 | 刚从清单写入，还没探测过 | 每次都重探 | 否 |

只有 `allowed` 会进候选池，其余四种只留下探测结论。

能跳过重探的只有 `allowed`、`forbidden`、`missing` 三种，它们都是有定论的结论。在 `--max-age` 窗口内重复执行时，这三种既不发起请求也不写库，且不占 `--limit` 额度。其余情况要么从未探过、要么结论是临时的，每次执行都会重探。`--max-age 0` 与 `--refresh` 等价，都强制全部重探。上游换了套餐或改了口径后，用 `--refresh` 重新探测。

遇到 401 时，命令立即终止并停用该账号。凭据被拒后，该账号后续结论不再有效；更换凭据后账号会重新启用，手工启用的方式见[启用与停用](/docs/accounts#启用与停用)。

冷却与失败计数的关系见[冷却与失败转移](/docs/accounts/failover#冷却与失败转移)。当一个账号一个可用模型都没探出来时，本次只写入探测结论，账号原来的模型列表不动。

在终端中运行时，stderr 输出一行原地刷新的进度：账号、已完成 / 待探测数、最近完成的模型。stderr 不是终端或指定 `--json` 时，这一行不输出，管道与 CI 日志中不会出现额外内容。

## 查看探测结果

```bash
lax model ls
lax model ls --provider deepseek
lax model ls --account ds
```

七列表格：模型、账号（带可达性，如 `ds(可用)`）、该模型在该账号上的有效出站协议、上下文长度、最大输出、该模型支持的协议、输入价 / 输出价（每百万 token）。

最后一项价格列显示的是合并之后的单价：账号覆盖价优先，其次供应商级标价，两者的关系见[模型单价](#模型单价)。两项都没有时写 `未定价`。

上下文长度、最大输出与支持协议来自同步时的上游清单，缺失时显示 `-`；账号可以对这些值做覆盖，覆盖后显示的是覆盖值。有效出站协议指这个模型实际会走哪种线协议：账号上的探测结果优先，其次才是该模型声明的协议与供应商默认协议。

无任何模型记录时会提示下一步执行 `model sync` 与 `model probe`。

## 模型单价

单价属于模型，不属于账号：同一家供应商的同一个模型只存一份标价。账号只在套餐价与公开标价不同时覆盖其中几项，其余继承标价。

| 价格层 | 存在哪 | 写入方式 | 什么时候用 |
| --- | --- | --- | --- |
| 供应商级标价 | 模型目录里这家供应商的模型行 | `model price set <模型> --in N --out N` | 上游公开标价；同一家上游的同一个模型只有一份 |
| 账号覆盖价 | 这个账号在这个模型上的行 | `model price set <模型> --account <账号> --in N …` | 这个账号签的是套餐价，与标价不同 |
| 账号级单价 | 已经不存在 | — | 旧版本写在账号上的单价在升级时搬成账号覆盖价 |

计价时取值顺序只有一条：账号覆盖价 → 供应商级标价 → 两者都没有就是未定价。

命令的确认行沿用旧叫法：供应商写作「厂商」，供应商级标价写作「厂商级标价」，指的是同一样东西。

```bash
lax model price set deepseek-v4-pro --in 2 --out 8               # 供应商级标价，一家一份
lax model price set deepseek-v4-pro --account ds --in 1 --out 4  # 只改这个账号的覆盖价
lax model price ls
lax model price ls deepseek-v4-pro --account ds
lax model price unset deepseek-v4-pro --account ds out
```

| 参数 | 说明 |
| --- | --- |
| `--in`、`--out`、`--cache-read`、`--cache-write` | 四项单价，单位都是每百万 token |
| `--provider` | 供应商级标价落在哪家供应商；不给时按模型名唯一确定，同名模型出现在多家供应商的目录里会报错并列出候选 |
| `--account` | 给这个账号写覆盖价；与 `--provider` 互斥 |

`set` 只写命令行上给过的几项，没给的保持原值，四项一个都不给是用法错误。

`unset` 的字段不带 `--` 前缀，是模型名之后的位置参数，一次可写多个。清不到的项不报错，重复执行结论一致。

价格要挂在目录里已有的行上：模型必须先由 `model sync` 或 `model probe` 写进目录，手填的方式见[添加账号](/docs/accounts#添加账号)。账号覆盖价还要求这个账号在这个模型上有行，也就是同步或探活过一次。

条件不满足时命令报错并指出缺哪一步，不会凭空插一行只有价格的空壳。

`0` 是合法单价，表示免费或已经打包在套餐里。负数是写法错误，命令以退出码 2 结束。

清掉一项不等于设成 0：账号覆盖价清掉后回到供应商级标价，供应商级标价清掉后这一项未知。缓存读写没定价时按输入价算。

`model price ls` 不给模型时列出目录里所有有价格的模型。给 `--account` 时每个价格格子并排显示「目录 | 有效」，有效价就是该账号实际计价用的值，与 `usage` 读的是同一份合并结果。

未定价与免费是两件事：未定价表示不知道多少钱，免费表示确实不花钱。用量汇总里前者显示 `未定价`，后者显示 `0.00`，见[用量汇总](/docs/usage#用量汇总)。

## 选号依据

参与选号的是可达性而非同步结果：`model sync` 只把清单写进目录并把该账号标为可用，`model probe` 得出的结论才真正决定能不能接。因此客户端必须填写探测通过的名称；填错的症状与排查路径见[客户端报「模型不存在」](/docs/faq#客户端报模型不存在)。

多个可用账号里挑哪一个，由优先级、冷却与会话粘性共同决定。详见[冷却与失败转移](/docs/accounts/failover)与[会话粘性](/docs/accounts/failover#会话粘性)。
