所有操作均以子命令提供，不含交互式界面。只有网关本身需要前台运行（`lax serve`），其余命令执行完即退出，不需要系统服务或后台进程。

## 命令一览

| 命令 | 作用 | 参数与示例 |
| --- | --- | --- |
| `init` | 创建配置目录、数据库与加密密钥 | [系统命令](/docs/cli/system#init) |
| `serve` | 前台启动网关 | [系统命令](/docs/cli/system#serve) |
| `account` | 管理上游账号：`add`、`ls`、`set`、`rm`、`test`、`enable`、`disable` | [账号命令](/docs/cli/account) |
| `provider` | 厂商、路由与附加请求头：`ls`、`add`、`set`、`unset`、`rm`、`header` | [供应商命令](/docs/cli/provider) |
| `model` | 模型清单、探活、单价与别名：`ls`、`sync`、`probe`、`price`、`alias` | [模型命令](/docs/cli/model) |
| `usage` | 按账号、模型或日期汇总用量 | [记录与排查命令](/docs/cli/records#usage) |
| `log` | 查看请求记录：`tail` | [记录与排查命令](/docs/cli/records#log-tail) |
| `call` | 手工构造一条对话请求，打印响应与选号过程 | [记录与排查命令](/docs/cli/records#call) |
| `decide` | 发一条 systemone 决策请求 | [决策请求命令](/docs/cli/decide) |
| `doctor` | 自检配置、目录、密钥、数据库与端口 | [系统命令](/docs/cli/system#doctor) |
| `version` | 打印版本 | [系统命令](/docs/cli/system#version) |

分组子命令的帮助只读代码里的说明，不访问数据库，因此数据库为空或配置缺失时也能查看。

## 帮助入口

```bash
lax --help
lax account --help     # 组级：用途与子命令清单
lax account add --help # 子命令级：参数清单
```

`account`、`model`、`provider`、`log` 四组均支持 `-h`、`--help` 与 `help` 三种写法。

`provider header`、`model alias` 与 `model price` 自带整页说明，内容包括用法行、值写法与示例；其余组只列子命令与一句摘要。

## 全局参数

| 参数 | 作用 | 默认值 |
| --- | --- | --- |
| `--json` | 以 JSON 输出 | 关 |
| `--config <路径>` | 指定配置文件 | `$XDG_CONFIG_HOME/lax/config.json` |
| `--db <路径>` | 指定数据库文件 | `$XDG_DATA_HOME/lax/lax.db` |

`--config` 与 `--db` 必须写在子命令之前，写在之后会报 `flag provided but not defined: -config` 并以退出码 1 结束。`--json` 每个子命令都注册过，写在子命令前后都生效。

## `--json`

每个命令均支持 `--json`，供脚本解析。输出分两条流：

| 流 | 内容 |
| --- | --- |
| stdout | 结果，单个 JSON 对象或数组 |
| stderr | 错误文本，不会与结果混在同一条流里 |

字段随子命令变化，各命令页面单独列出。共同约定：

- 空集合输出 `[]`，不是 `null`；
- 凭据一律只输出掩码，明文不进入输出；
- 上游返回的原始结构（如决策请求的 `answers`、`usage`）原样输出，不重新编码；
- `--json` 与进度行不共存：指定后 stderr 上不再画原地刷新的进度。

```bash
lax account ls --json | jq '.[].name'
lax model ls --json | jq '[.[] | select(.protocols | index("gemini"))]'
```

## 退出码

| 场景 | 退出码 | stderr 里会看到 |
| --- | --- | --- |
| 成功 | 0 | 无内容，结果在 stdout |
| 运行失败：上游报错、`model sync` 有账号同步失败、`model probe` 无模型探测通过、`doctor` 有检查项未通过 | 1 | `<子命令>: <现象与下一步>` |
| 用法错误：参数缺失、取值非法、地址格式不正确 | 2 | `<子命令>: 用法：…` 或具体原因 |
| 参数名拼错或参数值无法解析 | 1 | `flag provided but not defined: -config`、`invalid value "abc" for flag -limit: parse error` |
| 未知子命令 | 2 | `未知子命令 "nope"`，随后是完整用法 |

命令写错了看退出码 2，上游或本地数据有问题看退出码 1。参数名拼错是唯一落在 1 的写法问题。

## 错误信息约定

错误行以子命令名开头，随后给出下一步操作，不只转述上游原文：

```text
$ lax provider add acme --openai /v1/chat/completions --default-protocol openai2
provider: --default-protocol "openai2" 不认识，可用 anthropic、openai、responses、gemini、systemone（也认线协议全名 openai-chat、openai-responses），例如 lax provider add acme --base-url https://api.example.com --openai /v1/chat/completions --default-protocol openai
```

首段是子命令名，冒号之后是原因，最后给出可改写的命令。这条示例的退出码是 2，表示命令本身写错了。

供应商名不存在时，报错会列出已知供应商；名称接近时还会给出最接近的一项，编辑距离不超过 2 才提示。报错同时说明可以改用 `--provider <自定义名> --base-url <地址>` 直接建供应商，做法见[新增供应商](/docs/providers#新增供应商)。

## 常见报错

下表的「stderr 片段」是原文的一部分，可用它定位到具体一行：

| stderr 片段 | 含义 | 下一步 |
| --- | --- | --- |
| `尚未初始化，先运行 lax init` | 配置文件不存在，或 `--config` 指错了路径 | 运行 `lax init`，或核对 `--config` |
| `厂商 "x" 不在厂商表里（已知：…）` | `--provider` 的名称不在供应商表中 | 改名称或直接给 `--base-url`，见[新增供应商](/docs/providers#新增供应商) |
| `厂商不存在："x"` | 该供应商不在供应商表中 | `lax provider ls` 查看已知供应商 |
| `厂商 x 没有声明附加头 y（整个厂商）` | [`provider header unset`](/docs/cli/provider#header-unset) 的目标不存在，括号里是协议范围 | 先 `lax provider header ls` 看已有的头 |
| `--default-protocol "x" 不认识` | 协议取值只能是 `anthropic`、`openai`、`responses`、`gemini`、`systemone`（也认线协议全名 `openai-chat`、`openai-responses`）；`provider header` 的同一条报错写作 `--protocol "x" 不认识` | 换成其中之一 |
| `缺少凭据：--key <key>、--key - 从标准输入读，或环境变量 LAX_KEY` | `account add` / `account set` 没拿到凭据 | 三种提供方式任选一种 |
| `没有账号探出可用模型` | 账号已同步，但没有模型探测通过 | 重新执行 [`model probe`](/docs/models#探测可用性) |
| `还没有账号` | 账号池为空，先添加账号 | `lax account add`，见[添加账号](/docs/accounts#添加账号) |
| `一个问题都没拼出来` | [`decide`](/docs/cli/decide) 没拿到任何问题 | 用 `--noul`、`--choice`、`--score` 拼问题，或改用 `--questions` |
| `模型 X 以 … 协议出站，不是 systemone` | `decide` 选中的账号不跑决策协议 | 用 `provider set <供应商> --systemone /v1/systemone` 声明路由后重新探活，或换一个走 systemone 的模型 |

网关返回给客户端的错误体不属于这张表，那是 HTTP 响应而非命令输出，报文形状见[错误响应](/docs/gateway/errors#错误响应)。
