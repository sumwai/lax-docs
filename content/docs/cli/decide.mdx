---
title: 决策请求命令
description: decide 的参数、问题拼法、输出表与 --json 字段
---

`lax decide` 发一条 systemone 决策请求，把每个问题的答案打成一张表。协议本身（问题类型、上限、错误体）见[决策请求](/docs/gateway/decision)。

```bash
lax decide --model jev-latest --state '付款失败三天，损失在扩大，请今天处理' \
  --noul urgent='是否要求今天处理' \
  --choice team='该交给哪个团队' --choice 'team:billing=付款与扣款,technical=软件故障' \
  --score anger='情绪强度' --score 'anger:平静,不满,愤怒'
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `--model` | 必填；有效出站协议必须是 systemone，别名先按[模型别名](/docs/models/alias)解析 |
| `--state` | 必填；决策要看的材料，首字符是 `{`、`[` 或 `"` 时按 JSON 解析，其余按纯文本字符串发送 |
| `--questions` | 整块 `questions` 对象（JSON），与下面三个参数二选一 |
| `--noul` | `名=问句`，可重复 |
| `--choice` | `名=问句` 声明问题，`名:选项[,选项...]` 追加选项，可重复 |
| `--score` | `名=问句` 声明问题，`名:级别[,级别...]` 追加级别，可重复 |
| `--json` | 输出 `answers`、`usage`、`model`、`account`、`latency_ms` |

`--state` 不能为空。要发空字符串当材料时写 `--state '""'`。

## 问题的两种来源

| 来源 | 写法 | 输出行序 |
| --- | --- | --- |
| 逐条拼 | 可重复的 `--noul`、`--choice`、`--score` | 按命令行出现顺序 |
| 整块 JSON | `--questions '{"urgent":{"type":"noul","instructions":"…"}}'` | 按问题名升序 |

两种来源同时给属于用法错误。

逐条拼时，三类参数的写法与判据规则：

| 类型 | 声明问题 | 追加判据 | 判据规则 |
| --- | --- | --- | --- |
| `noul` | `--noul 名=问句` | 无 | 不需要判据 |
| `choice` | `--choice 名=问句` | `--choice '名:选项1=说明,选项2'` | 至少两个选项；写 `key` 或 `key=说明` |
| `score` | `--score 名=问句` | `--score '名:级别1,级别2'` | 至少两级，从低到高，只写级别名 |

判据先声明后追加：名字还没用 `名=问句` 声明过就写 `名:…` 是用法错误。

```bash
# 整块 JSON，适合问题多或由脚本生成
lax decide --model jev-latest --state '材料' --questions '{
  "urgent": {"type": "noul", "instructions": "是否要求今天处理"},
  "team": {"type": "choice", "instructions": "该交给哪个团队",
           "criteria": {"billing": "付款与扣款", "technical": "软件故障"}}
}'
```

## 用法错误

用法错误均以退出码 2 结束，stderr 带完整用法行：

| 情况 | stderr 片段 |
| --- | --- |
| 一个问题都没拼出来 | `一个问题都没拼出来` |
| 两种来源同时给 | `--questions 与 --noul/--choice/--score 同时给了` |
| 选择题少于两个选项 | `只有 1 个选项` |
| 打分题少于两级 | `只有 1 级` |
| 判据重复、空项、打分级别带了说明 | 指出是哪个问题、哪一项 |
| `--state` 以 `{`、`[` 或 `"` 开头但不是合法 JSON | `--state 的首字符是 "{"，按 JSON 解析失败` |

## 人读输出

一张表加一行用量：

```text
模型 jev-latest（账号 ts1，systemone，耗时 550ms）
名称    类型    答案          概率  置信度
urgent  noul    -             0.98  -
team    choice  billing       0.99  0.98
anger   score   1.08（不满）  0.91  0.86
用量 输入 386 / 输出 61
```

三列的含义按问题类型定：

| 类型 | 答案 | 概率 | 置信度 |
| --- | --- | --- | --- |
| `noul` | `-`，没有「选中的选项」可写 | 回答「是」的概率 | `-` |
| `choice` | 选中的选项 key | 该选项的概率 | 上游给的 `confidence` |
| `score` | 分数，`legend` 有对应级别时附名称（如 `1.08（不满）`） | 最接近那一级的概率 | 同上 |

上游没给的列写 `-`，不补 0；上游没给某个问题的答案时，那一行的答案列写「上游没有给答案」。

## `--json`

输出五个字段：

| 字段 | 内容 |
| --- | --- |
| `model` | 解析别名后的模型名 |
| `account` | 选中的账号名 |
| `latency_ms` | 这次请求的耗时，单位毫秒 |
| `answers` | 上游 `answers` 原样，不重新编码 |
| `usage` | 上游 `usage` 原样 |

## 错误与协议限制

上游返回非 2xx 时以退出码 1 结束，错误行以 `decide: 网关返回 <状态码>（<error_type>）：<message>` 开头，后接这次请求的记录查法（`lax log tail`）。

`decide` 只发 systemone 请求：模型以其它四种协议出站时直接报错，并给出改用 `call` 或换模型的命令。反过来，`call` 发不了 systemone 模型，见[记录与排查命令](/docs/cli/records#call)。
