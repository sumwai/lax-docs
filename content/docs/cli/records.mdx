这三个命令分别回答「花了多少」「刚才发生了什么」「现在通不通」。口径与判定规则见[用量与日志](/docs/usage)。

## usage

```bash
lax usage
lax usage --since 7d --by account
lax usage --since 24h --by model
lax usage --by day
```

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `--since` | 时间范围，写法为数字加单位：`h`、`d`、`w`，如 `24h`、`7d`、`3w` | `7d` |
| `--by` | 分组维度：`account`、`model`、`day` | `account` |

`--since` 只接受相对时长，不接受日期。写成 `2026-10-01` 会报 `时间范围写法不对`，退出码 1。

人读输出八列，最后一行是合计：

| 列 | 内容 |
| --- | --- |
| 账号 / 模型 / 日期 | 随 `--by` 变化的分组键 |
| 请求 | 请求数 |
| 输入 token | 归一化后的未命中缓存输入 |
| 输出 token | 输出 token |
| 思考 token | 上游上报的思考 token |
| 缓存读 token、缓存写 token | 缓存读写量 |
| 估算花费 | 按这一行的账号与模型现算，精度自适应：`0` 写 `0.00`，小于 `0.01` 写四位小数，其余两位；缺价写 `未定价` |

缺价时末尾说明有几行没计入合计并给出补价命令（`lax model price set`）；全部有价但合计为 0 时说明这些请求算免费；有缓存读写时提示缓存已计入花费。单价归属见[模型单价](/docs/models#模型单价)，公式见[用量汇总](/docs/usage#用量汇总)。范围内没有记录时输出 `最近 7d 没有请求记录`。

`--json` 输出数组，每项字段：

| 字段 | 内容 |
| --- | --- |
| `key` | 分组键 |
| `requests` | 请求数 |
| `in_tokens`、`out_tokens` | 输入与输出 token |
| `reasoning_tokens` | 思考 token |
| `cache_read`、`cache_write` | 缓存读写量 |
| `cost` | 估算花费，数值而非字符串；这一组全部缺价时为 `null` |

## log tail

```bash
lax log tail
lax log tail -n 50
lax log tail --follow
```

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `-n` | 条数 | `20` |
| `--follow` | 持续输出新记录，按 Ctrl-C 结束 | 关 |

人读输出十二列：

| 列 | 内容 |
| --- | --- |
| 时间 | `01-02 15:04:05` |
| 协议 | `入站→出站`，如 `anthropic→openai-chat`；两边一致表示直通 |
| 模型 | 请求名与真实模型名不同时写成 `fast → glm-4.6` |
| 账号 | 账号名；账号已删除时写 `-` |
| 状态 | HTTP 状态码，失败时带 `✗` |
| 输入、输出、思考、缓存读、缓存写 | token 数，未上报为 `0` |
| 耗时 | 毫秒 |
| 错误 | 上游原话，超过 30 个显示宽度截断 |

注意时间与耗时单位：时间列到秒，耗时列只写数字加 `ms`。

`--json` 输出数组，每项字段：

| 字段 | 内容 |
| --- | --- |
| `ts` | 记录时间，Unix 秒 |
| `inbound`、`outbound` | 入站与出站协议 |
| `model`、`model_used` | 客户端请求的模型名与实际使用的模型名；命中别名时两者不同 |
| `account` | 账号名 |
| `http_status`、`ok` | 上游状态码与是否成功 |
| `in_tokens`、`out_tokens`、`reasoning_tokens` | token 数 |
| `cache_read`、`cache_write` | 缓存读写量 |
| `latency_ms` | 耗时，毫秒 |
| `error` | 错误文本，成功时为空串 |

`--follow` 每秒拉一次新记录，按 ID 递增补打；`--json` 时每批新记录输出一个数组。

## call

```bash
lax call "<提示词>" [--model <模型>] [--protocol <协议>] \
    [--stream] [--max-tokens N] [--system <提示词>] [--debug]
```

`call` 在本进程内起一个临时网关（监听随机端口），再用真实 HTTP 请求打进去，走的是与外部客户端完全相同的路径。

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `<提示词>` | 位置参数，多个词拼成一段，不能为空 | — |
| `--model` | 模型名；留空取第一个账号的第一个模型 | 自动 |
| `--protocol` | 入站协议：`anthropic`、`chat`、`responses`、`gemini` | `anthropic` |
| `--stream` | 发流式请求 | 关 |
| `--max-tokens` | 最大输出 token | `256` |
| `--system` | system 提示词 | 空 |
| `--debug` | 把选号过程、实际请求地址与上游状态写到 stderr | 关 |

`--protocol` 不接受 `systemone`：决策请求没有提示词可发，该场景用 [`decide`](/docs/cli/decide)。模型的有效出站协议是 systemone 时同样在发请求之前报错并给出改用命令。

```bash
lax call "hi" --model deepseek-v4-pro
lax call "hi" --model deepseek-v4-pro --debug
lax call "hi" --model gpt-5.1 --protocol responses
lax call "hi" --model gemini-2.5-pro --protocol gemini --stream
lax call "讲个笑话" --system "回答不超过 20 字" --max-tokens 100
```

人读输出：

- 非流式：逐段打印文本；工具调用打印一行 `[tool_use] 名称 参数JSON`；`--debug` 时 stderr 追加一行用量与结束原因；
- 流式：anthropic、openai-chat、openai-responses 原样转出 SSE；gemini 逐帧解码后打印文本增量与工具调用；
- `--debug` 的轨迹以 `· ` 开头，与结果分属两条流。

`--json` 时非流式打印上游响应原文（一个 JSON 对象），流式时 gemini 的每个 `data:` 帧打印一行 JSON，其余协议原样输出 SSE。

上游或网关返回非 200 时退出码为 1，错误信息带状态码与响应正文。
