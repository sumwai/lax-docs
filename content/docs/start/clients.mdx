所有客户端都连接同一个网关地址。lax 不修改客户端自己的配置文件；需要手动把 base URL、鉴权头与模型名指过来。

## 地址与鉴权

| 项目 | 值 |
| --- | --- |
| 网关地址 | `http://127.0.0.1:4567`（缺省） |
| 鉴权 | 本机网关不校验入站凭据 |
| 客户端 key | 任意非空字符串，例如 `lax-local` |
| 模型名 | 必须是探活通过的模型名，见 `lax model ls` |

入站协议由路径决定，不靠 `Authorization` 头判断：

| 客户端类型 | 路径前缀 |
| --- | --- |
| anthropic | `/v1/messages` |
| openai-chat | `/v1/chat/completions` |
| openai-responses | `/v1/responses` |
| gemini | `/v1beta/models/{model}:generateContent` |
| openai-embeddings | `/v1/embeddings` 或 gemini 的 `:embedContent` |
| systemone | `/v1/systemone` |
| openai-speech | `/v1/audio/speech` |
| openai-transcriptions | `/v1/audio/transcriptions` |

## Claude Code

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:4567
export ANTHROPIC_AUTH_TOKEN=lax-local
export ANTHROPIC_MODEL=deepseek-v4-pro
claude
```

Claude Code 说 anthropic 协议，网关按这个账号的有效出站协议转换或直通。

## Codex

Codex 使用 openai-responses 协议，base URL 要包含 `/v1`：

```toml
# ~/.codex/config.toml
model = "gpt-5.1"
model_provider = "lax"

[model_providers.lax]
name = "lax"
base_url = "http://127.0.0.1:4567/v1"
env_key = "LAX_API_KEY"
```

```bash
export LAX_API_KEY=lax-local
codex
```

模型名取 `lax model ls` 里可用的一项。如果上游只提供 openai-chat，网关会从 responses 转到 chat。

## OpenAI SDK

Python：

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:4567/v1", api_key="lax-local")
resp = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "hello"}],
)
print(resp.choices[0].message.content)
```

Node.js：

```js
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "http://127.0.0.1:4567/v1", apiKey: "lax-local" });
const resp = await client.chat.completions.create({
  model: "deepseek-v4-pro",
  messages: [{ role: "user", content: "hello" }],
});
```

## Anthropic SDK

```python
from anthropic import Anthropic

client = Anthropic(base_url="http://127.0.0.1:4567", api_key="lax-local")
msg = client.messages.create(
    model="claude-sonnet",
    max_tokens=256,
    messages=[{"role": "user", "content": "hello"}],
)
```

Anthropic SDK 默认拼 `/v1/messages`，因此 base URL 不带 `/v1`。

## Gemini SDK

gemini 的模型名在 URL 路径里，不在请求体里。网关接受原生 `generateContent` 与 `streamGenerateContent` 路径。

```python
from google import genai

client = genai.Client(
    api_key="lax-local",
    http_options={"base_url": "http://127.0.0.1:4567"},
)
resp = client.models.generate_content(
    model="gemini-2.5-pro",
    contents="hello",
)
```

如果客户端不接受自定义 base URL，也可以直接用 HTTP：

```bash
curl -s http://127.0.0.1:4567/v1beta/models/gemini-2.5-pro:generateContent \
  -H 'Content-Type: application/json' \
  -d '{"contents":[{"parts":[{"text":"hello"}]}]}'
```

## 发现模型

不知道有哪些模型名可用时问网关：

```bash
curl -s http://127.0.0.1:4567/v1/models
curl -s http://127.0.0.1:4567/v1/models/deepseek-v4-pro
```

两个接口只读、只收 GET，不写请求记录，也不影响冷却与选号。停用账号提供的模型不会出现在清单里；冷却中的模型仍会出现。

## 常见接入问题

| 现象 | 先检查 |
| --- | --- |
| 401 / 403 | 本机网关不校验客户端 key；先看 `lax log tail` 里上游返回的状态 |
| 404 | 路径是否多了或少了 `/v1`；模型名是否在 `lax model ls` 里 |
| 400，提示模型不存在 | 客户端写的名字没有同步或探活通过；用 `lax model ls` 核对 |
| 503 | 候选账号都不可用或在冷却；看 `lax route explain <模型>` |
| 流式没有输出 | 客户端与入站协议是否匹配；`lax model call --stream` 先验证网关 |
