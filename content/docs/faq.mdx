## 网关无法启动

按顺序排查：

1. 执行 [`lax doctor`](/docs/install#环境自检)，六项检查里先修标 `fail` 的那些：
   - 配置文件缺失：运行 `lax init`；
   - 端口一项失败：地址已被占用，见下一步。
2. 端口被占用时更换监听地址，先确认占用的不是另一个遗留的 `lax serve`：

```bash
lax serve --addr 127.0.0.1:9000
```

3. 客户端中对应的 base URL 同步改成同一个地址，否则请求仍打到旧端口。

## 客户端报「模型不存在」

模型名必须与探测通过的名称完全一致，不做别名归一。先确认清单里有没有这个名字：

```bash
curl -s http://127.0.0.1:4567/v1/models
lax model ls
```

第一条需要网关正在运行，第二条直接读本地数据库。得到的结果对应三种处理：

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 清单里没有该名称，或 `/v1/models` 返回空数组 | 账号尚未同步，或没有模型探测通过 | `lax model sync --account ds` 后执行 `lax model probe --account ds` |
| 清单里有，转发仍返回 503 | 提供该模型的账号都在冷却或被停用 | `lax account ls` 看状态，见[请求持续失败并进入冷却](/docs/faq#请求持续失败并进入冷却) |
| 名称有多余空格或大小写不符 | 名称按原文匹配 | 从 `/v1/models` 的输出里复制 |

只由停用账号提供的名称在清单里是 404、直接转发却是 503，这个分界见[只读接口](/docs/gateway#只读接口)。

## 请求持续失败并进入冷却

冷却指账号失败后被暂时移出候选的一段时间。连续失败时这段时长会递增，规则见[冷却与失败转移](/docs/accounts/failover#冷却与失败转移)。

账号是否已进入冷却，看 `account ls` 的状态列：

```bash
lax account ls
```

状态列有三种取值：`正常`、`停用`、`冷却至 <到期时刻>`。最后一种写成 `冷却至 15:04:05` 这样的时刻。

冷却时长按上游返回码分档，随连续失败次数翻倍，上限 30 分钟：

| 上游返回 | 首次冷却 | 后续 |
| --- | --- | --- |
| 429 | 60 秒 | 每次失败翻倍，到 30 分钟封顶 |
| 5xx、超时 | 10 秒 | 同上 |

排查顺序：

1. `lax account test ds` 确认凭据本身还能用。
2. 失败信息里带 403 时多为套餐或模型权限问题，直接看上游原文，切换账号无效。
3. 冷却已到期但仍想立刻恢复，用 `lax account enable ds`，它同时清除冷却与失败计数。

同时配了多个账号时，一次失败只会把当前账号移出候选，请求已经切到下一个账号。

因此客户端可能表现为「偶尔慢一次」，而不是报错。

## 凭据被拒后账号被停用

401 会将账号停用，避免单个失效凭据导致整个候选池不可用。更换凭据后无需删除账号重建：

```bash
lax account set ds --key sk-new
```

该命令同时清除冷却与失败计数并[重新启用账号](/docs/accounts#启用与停用)。也可直接执行 `account enable ds`。

## 迁移到另一台机器

需要复制的文件与迁移后要确认的检查项见[备份与迁移](/docs/install#备份与迁移)。客户端不用改配置，base URL 仍是 `http://127.0.0.1:4567`。

## 是否可对外开放

默认只监听 `127.0.0.1`，不建议修改：网关不校验入站凭据，任何能够连接该端口的使用者都会消耗账号额度。

## 是否支持多机共用

设计目标为单人单机。多机共用同一网关等同于共享凭据，需要自行实现鉴权与隔离，超出当前范围。

## 数据流向

数据仅发往账号配置中的上游地址。凭据以 AES-256-GCM 加密后存储于本地 SQLite，明文不进入日志，也不进入 `--json` 输出。
